## 0. 先修正一件事：我上一份评估的对照物过期了

你说 128 是目标，现网卡珊德拉 64 是最初版本。那我上一轮算的 A vs C 全是在 **64** 上做的，**对照物本身是淘汰版本**。重算之后有一件事必须先讲清楚：

| 帧 | 尺寸 | 色值数 | 色块数 | 平均 \|ΔL\| |
|---|---|---|---|---|
| A 加尔文（已过） | 128 | **568** | **1385** | 6.09 |
| A 薇奥莱（已过） | 128 | **1195** | **2897** | 11.41 |
| C 卡珊德拉（本版） | 128 | 33 | 418 | 5.79 |
| C 卡珊德拉（未加 128 细节） | 128 | 32 | 406 | 4.71 |

**128 没有让 C 自动追上，反而把差距放大了**：A 的 128 帧用满了 4 倍像素（568–1195 色、1385–2897 块），而 C 的 128 只是把 64 的形放大两倍。色块比 0.30，局部色数比 0.50。

我也试过往 C 里补 128 级细节（发丝分缕 + 衣缝，半单位宽 = 128 上 1 像素）：

| | 加前 | 加后 | A（加尔文） |
|---|---|---|---|
| 平均 \|ΔL\| | 4.71 | **5.79** | 6.09 |
| 色块数 | 406 | 418 | 1385 |
| 3×3 色数 | 2.46 | 2.52 | 5.05 |

**\|ΔL\| 靠几根高对比线就追平了，但色块数只从 0.29 涨到 0.30。** 平均明度差会被少数强边"刷"上去，真正的细节密度看色块数和局部色数——那两项没动。所以别被 \|ΔL\| 追平骗了。

结论：**128 给 C 的是空间，不是自动的精度。要用上这个空间，必须按 128 重新设计一遍模型**（五官、褶、发缕都要重排）。我现在这具模型是按 64 的格子画的，放大到 128 只是"更干净的平涂"。

## 1. 你的理解对不对

> 由建模出骨架，让生图模型基于骨架和角色人设图补骨架上的角色细节

**方向对，三处要精确：**

**① 不是骨骼蒙皮，是"板片假骨架"。** 它没有骨骼权重，是一叠按深度排序的平面零件。对生图模型来说，它的作用是一张**结构控制图**：告诉模型轮廓在哪、关节在哪、脚底在哪一行、哪块是头发哪块是大衣。它不能旋转查看，也不需要——正交、朝右、`flipX` 已经够用。

**② 人设图不该被"贴"上去。** 立绘（`identity/source/h23.png`）只回答"这块是什么"：立领还是翻领、扣子几颗、绑带怎么缠。直接贴纹理会带来透视和光照冲突，而且立绘是 768×1344、战斗帧是 128——分辨率差 10 倍，贴上去只会糊。正确用法是**把答案写进模型的形状**（我这轮做的事），或者写进编辑指令。

**③ 关键区别：不是"重新画一个人"，是"在已定的块内加明暗"。** 指令必须写成"不改轮廓、不改姿态、只加布料转折和材质层次"。模型守不守这条，是整个方案成败的分水岭——这也是下面概率估计里最大的不确定项。

## 2. 相比"视频生成 + 抽帧"，优势在哪

先说清两者解决的不是同一件事：**视频生成解决"动起来"，抽帧的隐含假设是"生成的视频里恰好有对的帧"。** C 路线解决"每一帧的形都是指定的"。

| 维度 | C 定形 + 补细节 | 视频生成 + 抽帧（方案 A 的走） |
|---|---|---|
| 几何 | **确定性**。轮廓、身高、脚底由模型给定，十帧必然同高同行；锁定后轮廓逐像素一致 | 每帧都是采样。靠"抽"，抽不到就没有；抽到还要再入盒 |
| 姿态 | **指定**。contact / passing / down 是写出来的 | 不可控。你只能从它走出来的东西里挑 |
| 失败处理 | **可局部重来**。某帧细节不好只重跑那帧的 texture，几何不动 | 重抽会换人。所以有"两轮停手"的规则，两轮不过就停 |
| 成本 | 9 张 512 静图编辑（idle + 6 走 + 2 技能） | 跑 5 秒 ≈ 120 帧，只挑 6 帧。本机 H3 还限 0.4MP/5s |
| 扩展 | 同一具模型出攻击、受击、死亡、施法，不需要新生成 | 每个动作都要新生成一轮 |
| **纹理跨帧一致** | **弱。逐帧静图编辑没有时序约束**，同一件大衣在 6 帧里可能被画出不同的褶 | **强。视频天然有时序连贯** |

**最后一行是这个方案唯一的结构性短板，也是最可能翻车的地方。**

另外两笔账要记：

- 方案 A 的走循环现在是**卡住的**：Wan Animate 2 权重不在盘，本机 H3 只到 0.4MP/5s，加尔文走三轮没有过目图（`combat-scheme-c-prep-v1.md` §1）。所以"回退 A"不是回到一个能跑的方案，是回到一个在走帧上停住的方案。
- A 的 64 帧之间面积波动 20.2%，C 的 7 帧是 3.6%（其中 A 那部分不全是漂，迈步本身也会让轮廓变窄）。这项 C 占优，但不是压倒性的。

## 3. 成功概率

分三层给，因为这三层的不确定性差很多：

| 层 | 概率 | 依据 |
|---|---|---|
| **几何 / 帧间一致**（轮廓、身高、脚底、包围盒） | **≈0.95** | 确定性，不依赖模型。锁定脚本已跑通：A 的内部裁进 C 的轮廓，保留 88.5% 色块 |
| **单帧细节到 A 的 70–80%** | **0.55** | 上限证据：A 的 253 块里 224 块能落进 C 的轮廓，说明"形"不是障碍。反向证据：128 上加 6 块五官板，读成"胡子+咧嘴"——**补细节 ≠ 设计好细节** |
| **9 帧纹理不闪**（6 走帧并排看没有跳动） | **0.30–0.40** | 无现成依据，必须实测。这是最可能否掉整条路的一层 |
| **整体跑通并进游戏** | **0.45–0.55** | 前提是先做 P1（两帧查闪）且过；不过就退回下面 §4.3 的拆法 |

我给的这些数不保守也不乐观，是"愿意用一次生成去否证"的数。真正的价值不在这些百分比，在 §4 的三步——**每一步都有一个能直接否掉整条路的判据，且成本很低。**

## 4. 建议的试点顺序（每步都可否证）

### P0 · 一帧，判"补不补得出细节"
- 输入：`review/20261019-scheme-c/src/hero-cassandra.png`（512 平涂，已有）
- 1 次 Qwen-Image-2.1 编辑 → coverageDown 8 → 轮廓锁定 → 量
- **通过判据**：色块数 ≥ 200（A 253 / C 120）；躯干 \|ΔL\| ≥ 16，下摆 ≥ 9（现 6.6 / 2.4）
- **否证**：色块数 < 150 → 模型只在原块里涂了渐变，没加结构，这条路否掉。损失：一次生成。

### P1 · 两帧，判"闪不闪"
- idle + walk-a 两帧同一套流程
- **通过判据**：把两帧里大衣、头发两块的颜色直方图对齐，色块数差 ≤ 15%，且并排看不出同一块布换了画法
- **否证**：同一块布在两帧里被画出不同的褶 → 走帧这条路否掉

### P2 · 九帧
- 只有 P1 过了才做。做之前先定：技能帧要不要（技能动作大，闪最不明显，可以先做）

### 4.3 如果 P1 否掉，还有拆法
把"会闪"和"不会闪"的部分分开：

- **idle / `-v`**：两帧几乎同一姿势，闪不掉 → C + 精修可行
- **技能 a/b**：动作大、只有两帧、观众注意力在特效上 → 闪不明显，可行
- **六帧走**：闪最明显 → 继续用视频生成，或者接受平涂（不精修）

这样即使纹理一致性不过关，主角的 idle 立绘感和技能帧仍然能拿到 A 级的细节，走帧保持 C 的确定性。**这条路在任何一种结果下都不会全输。**
