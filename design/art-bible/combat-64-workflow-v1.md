## 1. 形锚（2026-09-06 · 主理人六点）

### 1.1 解析

生产里角色先锁 **形象套（model package）**，再画动作。形象套不是一张图，是同一套人的三层记录：

| 层 | 锁什么 | 本项目文件 |
|---|---|---|
| 剪影 | 远认：谁、多高、哪最宽、有没有第二团 | `characters/_shared/lineup/char-bible-party-lineup-v4.png`（排队）+ 各人 `characters/<id>/identity/silhouette/` |
| 立绘 | 近认：脸、发型、衣层、道具、材质 | `characters/<id>/identity/source/` 与 `portraits/`（服装/发/甲唯一蓝本；头从成片裁，不另开） |
| 战斗设计 | 64 语言下的色块与层次，**不是新外形** | `char-bible-combat-color-key-v2` + 形参 `idle-row1-v2` + 色参 `idle-v6` |

三层是同一套人的三种记录，不是三个可以互相改的设计。冲突时：轮廓听剪影，衣发脸道具听立绘，64 的色面积听战斗色键。色键若发明新发型、新衣型（魔化薇奥莱曾改成马尾军装），那是违例，不是「战斗层可以另开一套」。

**① 后续必须守这套。** 64 / 走 / 技能是这套人的实例，不是新设计。若真要新形象（另一形态、另一风格、另一套衣服），必须补齐剪影 + 立绘 + 战斗设计，登记为 **新的形象套**（可挂在同一角色 id 下，如守誓 / 魔化）。禁止只改 64、只改提示词就当新人。

**② 风格也是形象套的一部分。** 服装相近但画法不同 = 另一套。立绘绘画哥特、战斗硬色块、Q/章/可爱，是三条产品线，不是同一套人的三种滤镜。生成时在 Q 与写实之间横跳，等于中途换模型。战斗 64 既不是油画缩小，也不是 Q，也不是把油画 **硬切/BOX/中位色** 出来的副产品。它是立绘那套人 **按 64 语言另画的硬色块**。「降密度」是设计决定留哪些块，不是缩小算法。横跳或硬切出来的图，无论计量多绿，都不入本套。

**③ 形锚锁的是人，不是动作。** 站、走、技能都可以换姿态、换重心、换衣服随动。但不能换人：帽型、两层衣、灯、脸、马尾刃等，动作里必须仍在。元素出现或丢失必须可分类、可记录，不得「生成没了」或「管线吃了」当原因。

| 类别 | 含义 | 例 | 要不要改形象套 |
|---|---|---|---|
| 遮挡 | 还在，被肢体/衣挡住 | 走时灯被大衣挡一层 | 否 |
| 降密度 | 还在，块变小，仍能指认 | 灯体+焰心 2–4px，不是 0 | 否 |
| 动作位移 | 还在，位置因动作变 | skill 举灯，髋侧空 | 否 |
| 状态变体 | 形变了 | 魔化、破甲 | **要**，另开形象套 |
| 禁止 | 无记录消失或被管线挖空 | 脸没了、腹空心、斗篷变刺 | 本帧作废 |

**④ 管线是这套人的转写，不是作者。** 它只能抠真底、收进 token、装箱。不能改外形、不能改风格、不能把主体当背景挖掉。现网已见两类空心，管线 PASS 也救不了：

| 类 | 是什么 | 例（抽检） |
|---|---|---|
| 真洞 | 轮廓内 alpha 透明，不是设计开叉 | `enemy-necro` 体内 22 洞；`enemy-bonethrower` 233；`enemy-gravekeeper` 223 |
| 墨斑 | 像素不透明，但近 `(0,4,12)` / L\*≈0，读成碎马赛克 | `player` 约 35% 近墨；`player-walk-a` 同；C 已过帧约 5% |

`player` 的问题主要是墨斑不是真洞：身体还在 alpha 里，但夜布被吃成底色，脸和灯读不出来。`enemy-necro` 是真洞：腹心透明，丢的是主体像素。两类都算脱离形锚。

**⑤ 站姿 ≠ 步帧。** 站姿（idle）是静止持姿，只作走动的 **起点 / 停点**（离站前、刹住后）。步帧是行走持姿：接触、落下、经过，有自己的重心、下摆、灯相位。站姿可以锁头身比和形锚，**不能当步帧的画布**（分腿、扭曲 idle、只滑腿）。`archive/process-v1-deprecated/combat-64-parked-2026-09/edmund-walk-parked/` 整夹都是这个错：人还是站着的人，脚在换，所以不会有理想循环。

正确顺序：形象套已过 → 站姿按这套人画并过关 → **另画** 走姿关键帧（仍是这套人）→ 需要时再画站↔走的离站帧。离站是过渡，不是用站姿冒充走姿。

### 1.2 条文

1. 开工前写明本帧所属 **形象套**（剪影 + 立绘 + 战斗设计路径）。写不清不准生成。
2. 新形象或新风格 = 新形象套，三层补齐再画 64。
3. 生成参考只许本套三层 + 本套已过 64。禁止六人表、禁止 Q 参考画写实套、禁止未过现网当蓝本。
4. 动作不得换形锚。元素出入必须落在上表五类之一，并写进该帧记录。禁止类 = 废帧。
5. 管线输出必须仍是这套人，且 **实心**：无未设计体内透明；主体不得大面积近墨。不满足则废，即使 `--check` 绿。
6. 步帧必须按走姿画。禁止用站姿图变形当 walk。站姿未过，不准开步帧。

未过的现网帧可以留着跑游戏，但：

- 不得当参考图 #1（色/形蓝本仍是成片 + 色键 + C 已过套）
- 不得在它上面「只改腿」做出走帧
- 不得用 `process.mjs` 无 `--check` 的 Lanczos 再压一遍

## 2. 一帧的流程（门，不是建议）

按人、按帧。一次只做 **一个角色的一张动作**。先有形象套，再有动作。

| 步 | 做什么 | 停下来的条件 |
|---|---|---|
| 1 身份 | 写出形象套三层路径 + 本帧形锚清单 + 元素出入（§1.2） | 形象套或形锚写不清 → 不准生成 |
| 2 身份大图 | **可选。** 单人全身，只核「是不是这套人」。参考只用本套三层，不用六人表 | Q / 刺 / 第二套衣服 → 废这张大图。大图 **不是** 64 的切割源 |
| 3 出 64 | **按 64 语言直接画或生成** 一张硬色块单人帧。参考：本套三层 + 已过身份大图（只认人）+ 本套已过 64。入盒用近邻 | 从绘画大图 Lanczos / BOX / 中位色 / token 重涂 / 脚本补脸灯 → 废 |
| 4 自检 | §4 表全「是」。预览必须用 §5 过目板 | 有一条「否」→ 不准给主理人、不准写 `frames/` |
| 5 过目 | 只交：64 + 过目板 ×4 +（**走循环**才交 GIF）。技能只交该姿静帧 | 主理人未回「过」→ 停 |
| 6 入现网 | 直接写权威 64；raw 用 nearest-up 存档。`--check` + `pack` | 未过而写入 = 流程事故 |
| 7 归档 | 废稿进 `_park/`，根目录不堆 | 过程稿留在 lock 根目录 = 流程事故 |

步 2 过了只锁定身份，不自动授权步 3 去切它。卡珊德拉能切，是因为源已经是战斗色块语言（色键 / idle-v6 格），不是因为 BOX 算法能消化油画。艾德蒙夜布更暗，绘画大图硬切只会更糟。

走帧额外：

- 站姿 **已过** 之后才开步帧。站姿未过，不准做 walk。
- 步帧按 **走姿** 另画，不是站姿分腿 / 扭曲。上身、斗篷、灯必须有相位。
- 站姿只作走动起点 / 停点；离站帧是过渡，不能代替走姿关键帧。
- 2 帧只动腿一律不过。
- 技能帧：PNG 里不画环、粒子、拖尾。元素位移（举灯）须记入「动作位移」。
- 不同技能姿禁止做成联动 GIF（R22）。抽卡可以用两格条保证「条内同一人」，过目仍拆成独立静帧。
