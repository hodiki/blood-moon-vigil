# 旧版美术圣经审核（art-bible v0.3）

> 日期：2026-09-04 · 作者：林绘澄（美术总监）
> 对象：`art-bible.md` **v0.3**（垂直切片 Demo）及其下游。
> 落实：**2026-09-04 已写入 `art-bible.md` v1.0。** 本文保留为推翻依据，不再当现行条款。
> 立场：v0.3 只作 Demo 追溯。正式视觉以灯下哥特 + 角色圣经 + art-bible v1.0 为准。

---

## 0. Demo 里该留的

这些不是造型语言，是工程与可读性底线，正式版仍该守：

- 背景 L\*≤18、UI 文字 ≥4.5:1、图形 ≥3:1。
- 触区 44px / 字号下限 / 双端设计空间的**存在**（是否继续「横屏 1080 + 竖屏 1280 两套完全独立」另议）。
- 粒子池、draw call、禁全屏红晕、禁长震屏。
- 信息**双编码**（色 + 形）：危险区、治疗、经验——对象是 HUD/地面，不是角色皮肤。
- 帧名契约、图集拆包、PNG+alpha。
- 可访问性：色盲替换、减少闪烁、字号 125%。高对比模式可以有，但**默认皮肤不该等于高对比描边**。

---

## 1. 总述层：把 HUD 办法写成了世界观

§1 三关键词「暗夜血月 / 高对比剪影 / 红色即危险」把**解题循环的色标**写成了**美术风格**。Demo 的实际观感是：棋子级平涂剪影 + 冷青光环，不是灯下哥特。

隐患：正式立绘已经是半写实绘画，局内若继续执行这三句，会永远两套产品。入口已改余辉金/铁石框，局内仍停在切片口径，裂缝会越拉越大。

**建议推翻**：总述改成灯下哥特（形与材质可读、光在灯/烛/金属内部）。「红即危险」降为**地面与受击**的语义，不再要求「凡敌人皆整身暗红」。

---

## 2. 色彩系统：14 token 当皮肤，语义过载

§2「高饱和只用于信息载体、颜色不用于装饰」在 32px 程序剪影阶段合理，在 64px 角色/怪物上会毁掉设计。服装色、兽毛、甲油都不是「装饰噪声」，是形象。

同一颗 token 兼职过多：

| token | Demo 用途叠了几层 |
|---|---|
| `#FFC93C` 琥珀金 | 宝箱、武器稀有、Boss 金饰、局外余辉 CTA、立绘灯焰 |
| `#54E6C9` 冷青 | 玩家描边、提灯、准星、HUD、升级选中、召唤物边、减速、环绕球、摇杆 |
| `#7E1E1E` 暗红 | 全部普通敌填充、魔化角、加尔文滚边、卡珊德拉大衣派生 |
| `#2A3B2E` 草绿 | 地形草叶、加尔文披风派生 |

隐患：灯焰若用金 = 拾取；大衣若用暗红 = 敌人；狼披若用橄榄 = 草地。这不是角色设计失败，是**语义槽位不够**。方案 B 不是申请新色相就能了事，要先**拆槽**：金分「焰 / 拾取 / CTA」、红分「危险区 / 敌体 / 角色点缀」、冷青退出角色皮肤。

「不申请新色相」可暂留（B 先用同色相派生：压饱和酒红、压亮月银、焰心金面积上限）。若派生仍撞车，再单独立项加色，不在 Demo 14 色里硬挤。

---

## 3. 轮廓光：条款自相矛盾，且会吃掉 64px 形

已在 2026-09-04 评过，记入正册：

- §3 写「统一 Phaser FX 描边：敌我 2px…」
- §4 写「普通敌无描边」
- 工程 RV-C1：尸潮禁止 postFX（draw call）
- TA `outlineW=0`：外部轨不后置；要描就画进 PNG、吃安全框
- 移动端 Boss 描边关

**不是必须的。** 64×64 上 2px 边会吃掉帽檐/角/马尾刃。PNG 烘焙破坏走循环与图鉴复用；FX 与像素稿不对齐。

**建议推翻**：角色/怪物 PNG 不画轮廓光；敌我靠明度差 + 剪影；描边只作 §9 高对比可选。灯下的光画在形内部（焰、金属高光），不是外圈色标。

---

## 4. 角色规范：一人剪影冒充四人，尺寸口经分裂

§3「玩家 = 圆帽披风」、§4「32px 基准」、silhouette-v35「帽檐成为全身最宽」——全是 Demo 守夜人程序剪影的补丁，已经：

- 被角色圣经推翻（中檐、马尾刃、狼首、双线薇奥莱）
- 被 asset-spec v1.3 升到 64 档，但 art-bible 正文没改
- 现网 PNG 已是 64×64，程序兜底仍是 32×32 图集

隐患：任何按 v0.3 交稿的人都会画出「四个宽檐白棋子」。加尔文现网读成骑士、卡珊德拉没有马尾，就是这条的产物。

**建议推翻**：玩家层级描述改指向角色圣经；删除「圆帽披风 / 宽檐为最宽 / 32px 基准」。碰撞半径继续与视觉脱钩（这条 asset-spec 是对的）。

---

## 5. 敌人：层级编码绑死平涂，怪物没有形象

§4 三要素「体型 + 色相 + 角饰」把普通敌锁成**同一暗红填充**。16 种敌 + 方阵在 Demo 里只能靠外轮廓差几个角，潮中可读，图鉴/叙事不可读。精英再加幽紫描边 + 双角，是在已经够用的体型差上叠 HUD。

隐患：正式怪物若继续「凡红皆敌体」，忏悔者、腐朽骑士、石甲狼都无法穿自己的衣甲与锈蚀，只能当色盲色标。R-A 还禁止加尔文狂化翻红——合理的是「不要整身变敌色」，不合理的是「玩家侧永远不许出现暗红点缀」。

**建议推翻**：普通敌允许材质与局部色，只要**整体明显暗于玩家**、危险区/受击仍走血橙红。精英身份以 96 档 + 剪影角饰为主，不靠 3px 紫边。Boss 金饰不要和拾取金抢同一读法（形：王冠/权杖 vs 箱）。

---

## 6. 镜头与参考：俯视 Kenney ≠ 灯下哥特

§8 首选 Kenney Topdown Shooter / Roguelike。asset-spec 仍写「俯视 2D、K1 换色板」。现网战斗帧其实是 3/4 站立像素，立绘是半身绘画。

隐患：按 Kenney 备料会得到顶视角胶囊人，和风格帧、排队剪影都不接。silhouette-v35 还在 32 屏像素上加帽檐，是「看不出是啥」的补丁，不是造型方向。

**建议推翻**：备料参考改为角色圣经锁形 + 灯下哥特；战斗镜头写清为 **3/4 站立、只 flipX**（与现网一致），不要再写俯视顶视角。Kenney 只可作碰撞/灰盒，不可当视觉目标。

---

## 7. 双端与 LOD：两套设计空间 + 描边当 LOD

§8 桌面 1920×1080 横屏 / 移动 720×1280 竖屏「独立、互不裁切」。世界实体却要求双端同一规格。结果是 UI 两套、角色一套，文档却暗示两套画布。

silhouette-v35 用「缩到 16px 自然丢掉帽带」当 LOD。这是把**亚像素丢失**当成功能，细节没有主动设计。

隐患：正式 64px 角色若仍假设「手机上看成 16px 色块」，会不敢画材质，又退回平涂。

**建议**：双端 UI 空间可保留；世界精灵以 64 档一档为准，手机靠相机/缩放，不靠描边厚度、不靠「丢掉 1px 特征」。真要 LOD，另出 32 档或关掉内部高光，而不是外圈光环。

---

## 8. 特效与 UI：冷青垄断「玩家侧」

§6 升级卡选中冷青、§7 受击白闪/红闪、摇杆冷青——Demo 把「属于你的一切」涂成同一冷青。入口已改余辉金，局内 HUD 仍冷青，形成**局外灯下、局内赛博描边**。

隐患：方案 B 若只改角色帧、不碰 HUD/弹体/摇杆，战斗画面里角色已经哥特、周围一圈仍是冷青 UI，会像没换完皮。B 开工时要列「角色帧 / 召唤物 / 弹体尾羽 / HUD 选中」是否同批收束。

---

## 9. 文档网：同一句话三处三种意思

| 题目 | v0.3 | 下游 | 现网 |
|---|---|---|---|
| 描边 | 全员 FX | spec 后置 → 又改 `outlineW=0` | 敌无、玩家烘焙或画进 PNG |
| 玩家尺寸 | 32px | spec 64px | PNG 64、程序图集 32 |
| 玩家形 | 圆帽披风 | v35 宽檐最宽 | 角色圣经中檐+破斗篷 |
| 风格 | 高对比剪影 + 可 Kenney | 细致哥特升档 | 入口灯下哥特、局内仍切片 |

隐患：TA/美工不知该听哪一份。正式版必须以**一份新 art-bible** 覆盖 v0.3，并在索引里把 v0.3 标成追溯，不要靠角色圣经在局部打补丁。

## 10. 推翻优先级（供新圣经起草，仍不开工）

| 优先级 | 推翻什么 | 不推翻什么 |
|---|---|---|
| P0 | 默认轮廓光；玩家=圆帽披风；凡敌整身暗红；颜色禁止当服装 | 对比度/触区/性能预算；帧名；危险区仍要红+形 |
| P0 | 金/青/暗红语义过载（拆槽） | 14 token 可先派生，新色相另批 |
| P1 | Kenney 俯视作为视觉目标；32px 基准正文 | 碰撞与视觉脱钩 |
| P1 | 冷青垄断局内玩家侧（与入口余辉金对齐策略） | 局外余辉金 CTA（已锁） |
| P2 | 横竖完全独立两套世界规格是否过度 | 双端 UI 出档 2x/1x |

与方案 B 的衔接：B 是 P0 的落实方式（战斗层自有色与光，不是立绘缩小，也不是月银+光环）。**色键未出之前，不重画 `player` / `hero-*` / 敌帧。**
