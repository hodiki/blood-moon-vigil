## 0. 先读这一页

### 0.1 目的与思路可达吗——部分可达，思路要改一处

目的「用大模型给游戏备齐美术素材」按层回答，不能一刀切成能或不能：

| 层 | 可达？ | 条件 |
|---|---|---|
| 角色立绘 / 身份底 / 选人卡 | **全部可达** | 现网 WAI + GenerateImage 已证（H23、四人身份锁） |
| 环境 / 地砖 / 装饰 / UI 图标 | **全部可达** | 没有身份问题；批次 1 / 2 早已在 `frames/`，不是瓶颈 |
| 战斗 idle 128 / 192 | **可达** | 印戳 → 近邻入盒，两枪约一半过（守誓 idle、Vf1 B-lo 两例） |
| 技能静姿 / 走循环 128 | **有条件可达** | 换 C 轨作者（编辑模型或动作迁移）+ 人挑帧 + TA 门禁。是「AI 出稿、人终审」，不是全自动 |
| 换服装 | **有条件可达** | 立绘级：编辑模型换件 / try-on。永久换装 = 新形象套（现行条文正确） |
| 风格横跳（Q ↔ 写实） | **不当作可达** | 风格 = 另一套形象。立绘级能转；战斗硬色块不能当滤镜 |
| 64 直出硬色块 | **不可达（也不该追）** | 评 C 已定：新帧 128，近邻放大到同一占地 |
| 无人值守过关 | **不可达** | 2026 所有像素产线仍是「生成 → 挑 → 设参考 → 修」 |

思路「① 立绘 → ② 基于立绘生成动作 / 服装 / 像素」方向对（与 2026 社区「先入库再创作」同构），但 ② 要改写成：

**立绘 → 已过印戳（战斗侧唯一参考）→ 编辑模型 / 动作迁移一次出多相位 → 人挑帧 → 印戳 → 近邻 128。**

不是「拿立绘直接抽下一张」，也不是「在已过 idle 上 img2img 碰姿」。

## 3. 第②步为什么一直失败

### 3.1 工具类错位（主因）

img2img 是把底图加噪再去噪。姿势住在低频结构里：低 denoise 保结构就保住姿势（不改姿），高 denoise 丢结构就丢人。C1 / C2 0.40「没改姿反倒改了脸」、Ostris 两枪仍垂手，都是这个性质，不是参数没调到。账本自注已到墙边：「thedeoxen 训练默认是 denoise 1 空 latent；合法低 denoise 可能就是这堵墙」。

社区亦证实 stock Krea 2 未做参考训练，`ReferenceLatent` 挂上去会被忽略——所以 Klein / Krea 参考「没方案」的诊断是对的，只是没有接着写方案，而是退回了 i2i。

2026 年解决「同一人换姿 / 换装」的两类工具：

- 参考图在上下文里的**指令编辑模型**：Qwen-Image-Edit-2509 / 2511、FLUX.2 Klein 编辑模式、Krea 2 社区 Identity Edit LoRA。
- 以驱动视频做**动作迁移**：Wan 2.2 Animate、Wan Animate 2。

二者都在满降噪 / 空潜空间下工作，身份来自上下文里的参考 token，不来自提示词。现行条文「禁 EmptyLatent / denoise 1」是针对「OpenPose + 纯 t2i 重画衣服」写的，那条仍对；但它按 denoise 数值判合法，把这两类对症工具一起禁掉了。

### 3.2 像素层的作者是绘画模型

现网 128 = 绘画印戳近邻缩小。对单张 idle 成立；但每个新姿都要先在绘画域对齐再降阶，把最难的一致性推进了最难的域。专用像素工具（PixelLab 一类）在 64–200px 原生带骨架 / 参考做 8 向和动画，正是「同一棋子、走循环」这个问题的形状。代价：风格未必贴 H23 派生的 128；外部服务，需主理人授权（备选 A）。

### 3.3 8GB 天花板

RTX 4070 Laptop 8GB。Krea 2（12.9B INT8）能跑；Wan 2.1 I2V 14B fp8（16.4GB 文件）靠 lowvram + 共享内存跑过 480×832 × 17 帧。但 Qwen-Image-Edit 在 8GB 只能 Q3_K_S 带 offload 且画质打折（12GB 起可用，16GB 舒适）；Wan 2.2 Animate 14B Q4 / Wan Animate 2 INT8 属边缘。任何「换工具类」都要先回答算力从哪来。

### 3.4 治理成本高于产出

两枪封顶对随机采样是对的，但也让每个新工具只能靠两次猜测被判「不行」——Ostris 骨架、Wan I2V 都在找到工况前就停。三层分别锁再回头对齐已被证明会打架（魔化领 / 手套 / 发），单源派生是正确修正。条文仍在日更，助理时间大半花在账本上。

### 3.5 项目里已被证明、但没写成原则的规律

两套过关的走循环都不是「跨枪对齐」出来的：卡珊德拉的源本身是色键语言；艾德蒙 V4 是**单人六相位条一次生成**再裁。六张独立签混编从没过。**一致性最便宜的来源是同一次采样（一条、一段视频），不是事后对齐。** 新架构应把它写成原则，而不是只写成 R6 的例外。
