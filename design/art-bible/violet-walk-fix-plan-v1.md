## 1. 我这次错在哪

我拿 **S1 的 3/4 站姿（516）** 直接当了 Wan 的参考图。

模型接到的任务是「让她朝右走」，但它拿到的第一帧是**四分之三正面站姿**。于是它只能自己完成两件事：

1. **把她转成侧面** → 所以出现"转身"（正是你说不需要的帧）
2. **为了留住画面里的她/光球，把镜头推近** → 内容高从 596 涨到 665（+11.6%）

换句话说：**放大和转身是同一件事的两个表现**——都是"模型在补我没给它的信息"。

## 2. 既有解法（卡珊德拉已跑通）

仓库里 `queue-cassandra-stamp.mjs` 有一个 **`profile` 模式**，它不另写一套提示词，只替换姿势句：

```js
// 3/4 站姿 → 正侧身
"standing, body three-quarter toward the viewer's right,"
  → "standing in a perfect side view profile facing the viewer's right,"

// 头也跟着转
"head turned slightly toward the viewer so one eye is visible."
  → "head level, facing along the profile, one eye visible in the profile."
```

产出物在 `characters/cassandra/review/20261021-scheme-a-128/raw/profile-*.png`（768×1344，正侧身朝右），**这张才是喂给 Wan 的首帧**。

第三张图就是她的侧身印戳：正侧、朝右、双臂自然垂、腿可见。

## 4. 两个要你定的点

**① 侧身印戳要不要带「抬腿」**

你提到「类似 f00049 那样的侧身抬腿」。卡珊德拉的 profile 是**并腿站立**，抬腿交给 Wan 的驱动去做，结果是对的。

- **A（跟卡珊德拉一致）**：侧身并腿站立。稳，已验证
- **B（更贴近你说的）**：侧身 + 前腿微抬。理论上更省事，但**没验证过**，且抬腿姿态容易被 Wan 再放大

我建议 **A**，先复现已验证的路子；不成就再试 B。

**② 要不要顺手出 `-walk-s`（离站一帧）**

引擎里有这个槽：`walkStartFrame()` 找 `${base}-walk-s`，从 idle 切走时播一次。现在**只有艾德蒙有**（`player-walk-s.png`）。

- 有它：idle（3/4）→ 走（侧面）之间有一帧过渡，不会硬切
- 没有它：直接切，6.5fps 下多数情况看不出来

我建议**先不做**，等六帧跑出来在游戏里看不出硬切就算了。
