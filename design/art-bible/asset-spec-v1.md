## 0. 契约总则与快速索引

### 0.1 双轨美术（D3）定义

| 轨道 | 内容 | 触发条件 |
|---|---|---|
| A · 外部素材（本规格书） | 用户按本契约自备/购买 CC0 素材，M4 替换程序占位 | 用户交稿通过 §5 验收 |
| B · 程序剪影 v3.5 兜底 | `procedural-textures.ts` 程序生成剪影级资产，帧名契约不变 | 素材未到 / 验收未过，不阻塞管线 |

**替换铁律**：引擎只认「帧名」，不认「画得多好」。外部素材只需把帧画成同名 PNG 并重建图集，实体代码零改动（见 §4.3）。

### 0.2 十条硬规则（交稿前自检）

1. 帧名 = 引擎引用名，全小写 ASCII、连字符分隔、无中文/空格/大写（§2.1）。
2. 帧名契约延续 Demo：`player / player-v / enemy-* / enemy-boss / missile / orb / shockwave / gem / tile-ground / tile-grass` 等保留名**不可改名**（§2.1.1）。
3. 主体剪影 ≤ 帧宽 90%，四周留 ≥5% 安全边距；关键帧内容坐标上限见 §2.2。
4. 图集 ≤2048²、TexturePacker JSON 数组、`premultipliedAlpha=false`、tile 2 次幂 64×64（§2.3）。
5. 只用 art-bible 14 token 色（+2 草地 token）或其同色相 alpha 派生；**不引入新色相**（§2.4）。
6. 背景 L\* ≤18；**玩家/召唤物**剪影 L\* ≥45（月银白主体）；暗红普通敌靠剪影形状可读，描边编码正确可豁免 L\*≥45；UI 文字 ≥4.5:1、图形/图标 ≥3:1（§2.4）。
7. 描边编码三要素：体型 + 色相 + 角饰；玩家冷青 2px / 精英幽紫 3px / Boss 猩红 4px；描边禁止与背景同色系。**外部 AI 轨：描边由管线后置，原图不画描边**（§2.2 / asset-prep）。
8. 红 = 危险，金 = 稀有，绿 = 治疗，蓝 = 信息；颜色只用于信息载体，不用于装饰（§2.4）。
9. 双编码：危险=红+三角、治疗=绿+十字、精英=紫+双角、经验=蓝+菱形；形状优先于颜色（§2.4）。
10. 世界实体双端共享同一规格；UI 桌面 2x / 移动 1x 出档（§2.5）。

### 0.3 与 M1a 内容设计的接口（已对齐）

> **守夜人·艾德蒙——提灯=核心标志道具（v1.1 新增，world-bible §2 圣辉机制 + narrative §3.1）**：提灯是「末代提灯人」的身份锚点——提灯认血，只有他能重新点亮祖传之灯，灯里是初代守夜人留下的最后一点圣辉。视觉规格：
> - **手持槽（v1.3，32 档预算 ×2）**：灯体 **8×10 px**（帧内贴右手/髋侧）、提柄 3px 月银白 `#E8F0FA`；灯芯光点 **≥4px** 冷青 `#54E6C9` 常亮（呼吸 α0.85→1.0、1s），圣辉余晖 = 冷青光晕 **r≤10**（token 冷青同色相 alpha 派生，不新增色相）。64×64 帧禁止 20px 级灯体（会吃掉帽檐与边距）。
> - **提灯认血**（双态双编码）：常态灯芯 = 冷青圣辉（守夜人身份）；受击/濒死 0.6s 灯芯转暗红 `#7E1E1E` 警示（复用 token，非持续态；与濒死心跳 cue 同触发）——**不把提灯常态改成血色**：血色灯芯是 boss-01 血月尊者的镜像语义（world-bible §9 镜像表：灯在初代血脉手里是圣辉，在血月手里是血色）。
> - **帧归属**：`player` / `player-v` 帧内手持绘制（不新增引擎帧名，帧名契约不变）；如需特写（图鉴/结算/序章），加 1 帧 `player-lantern-close` 道具槽 32×32（characters 图集，**打包素材、不进入引擎引用表**，可选）。
> - **剪影兜底**：程序剪影已落地「锥顶宽檐帽 + 披风 + 冷青提灯」（§4.2）；外部素材须保持同一像素预算（帽檐约 52px 为全身最宽、灯体 8×10、灯芯 ≥4px）。程序剪影仍按 32 档绘制，局内替换以外部 64 帧为准。
> - **玩家填色铁律（v1.2）**：不透明填充以月银白 `#E8F0FA` 为主体；墨夜蓝黑 / 暗紫灰只许 1~2px 褶。禁止把海军袍当主色（量化后 32px 会变成青边黑团）。

### 2.4 色板与对比度约束

**14 token 色板（art-bible §2 + 2 草地 token）**：墨夜蓝黑 `#0B0E14` / 暗紫灰 `#131722` / 暗草绿 `#18201C` + 草叶 `#2A3B2E` / 月银白 `#E8F0FA` / 冷青 `#54E6C9` / 暗血红 `#7E1E1E` / 幽紫 `#B06AF0` / 猩红 `#FF3B3B` + 金 `#FFC93C` / 血橙红 `#FF3B30` / 电光蓝 `#4FC3F7` / 青绿 `#43D17C` / 琥珀金 `#FFC93C` / 纸白 `#F2F5F9`。

**约束**：
1. 只用上表 token 色或其**同色相不同 alpha** 派生；**禁止新色相**。
2. 色彩语义：红 = 血 = 危险；绿 = 安全/治疗；金 = 稀有/奖励；蓝 = 经验/信息；银（月银白 `#E8F0FA`）= 守夜会锻造 / 银器语义。颜色只用于信息载体，不用于装饰。
   - v1.1 双编码示例：血月猎手银制月光箭 = 银质通道（箭体月银白）+ 月光通道（尾羽/拖尾冷青）——银与月光两语义叠加在同一枚弹体上，色盲下仍可辨（形状：箭头高亮 + 尾羽）。
3. 亮度对比度硬标准：背景 **L\* ≤18**；**玩家 / 英雄 / 召唤物**主体剪影 **L\* ≥45**（月银白填充）；暗红普通敌（`#7E1E1E`，L\*≈15）**豁免 L\*≥45**，靠剪影形状可读，精英/Boss 另加描边编码；UI 文字 **≥4.5:1**；图形/图标 **≥3:1**。
4. 描边编码三要素（体型 + 色相 + 角饰），任意两要素可区分，色盲下仍可辨。
5. 描边线宽：玩家冷青 2px 常亮 / 精英幽紫 3px / Boss 猩红 4px / 普通敌无（靠剪影）；**描边禁止与背景同色系**。
6. 双编码形状：危险=红+三角、治疗=绿+十字、精英=紫+双角、经验=蓝+菱形；形状优先于颜色。
7. Standard 级替换色板：Protanopia / Deuteranopia 两套（M3/M4 出档），切换后仍 ≥3:1；**形状资产必须独立于颜色可辨**。
8. 特殊标记色域（§2.6）：幽紫=光环/召唤（敌方魔法语义）、冷青=玩家侧信息（标记/减速/圣辉）、红=蓄力/投射预警（危险语义）。

### 3.6 预算汇总与移动端降级

| 项 | draw call 增量 | 粒子 |

### 5.2 命名冲突检查方法

1. M2 期工程导出**帧名注册表**（JSON：图集 key → 帧名列表）。
2. 交稿前：`frame-name diff` 脚本——交稿帧名集 vs 注册表，须为「注册表 ⊆ 交稿集」且无多余名。
3. 冲突即拒：保留帧被改名 / 新帧重名 / 撞保留帧——一律打回。

### 5.3 对比度验收方法

- 工具：取色脚本读帧主色/描边色 → sRGB 计算 L\* → 对 §2.4 标准断言。
- 兜底经验值：背景 `#0B0E14`（L\*≈3）~ `#131722`（L\*≈8）~ 草地 `#18201C`（L\*≈13）。玩家/召唤物填充须落在月银白（L\*≥45）；暗红敌 `#7E1E1E` 不按 L\*≥45 打回，按剪影形状 + 描边编码验收。
- 图标：`#131722` 卡底上图形 ≥3:1；文字（DOM）≥4.5:1。

```
用户交稿 → 美术预审（§5.1 全项，打回 ≤2 轮）→ 替换冒烟（M4 集成门：重建图集 + 实体零改动跑通）

```
