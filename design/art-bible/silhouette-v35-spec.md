## 1. 根因分析：为什么 v3 在真实游玩下"看不出是啥"

### 1.1 渲染事实（先钉死）

- 玩家帧 32×32，中心 (0,0)，相机 zoom=1，无 setScale → **桌面 1080p 实渲染 = 32 屏像素**（32/1080 ≈ 3% 屏高）。
- `game-config.ts`：`antialias:false + pixelArt:true` → 像素锐利但**无抗锯齿**，1px 细节不糊但也不"融合"，呈现为生硬噪点。
- 玩家描边：`outlineScale=1.12` 烘焙 → 可见描边带 ≈ **0.12 × 距中心距离** ≈ 轮廓极值处 1.6–1.8px、靠近中心处仅 0.5–0.7px。

### 1.2 像素级论证：v3 的辨识全部落在 <3px 细节带

| v3 特征 | 帧内尺寸 | 32px 实渲染 | 16px 实渲染 | 判定 |
|---|---|---|---|---|
| 帽带（P0-1b） | 20×1px | 1px 横线 | 0.5px → **丢失** | <2px 失败 |
| 三边开衩（P0-1c） | 1.5px 宽 × 7px | 1.5px 线 | 0.75px → **丢失** | 亚像素 |
| 提灯灯体（P0-1a） | 3×4px | 3×4px | 1.5×2px | 临界 |
| 提灯光晕（P0-1a） | r2.8 @ α0.22 | 5.6px 极淡 | 2.8px 更淡 | 淡到不可辨 |
| 帽冠圆顶 | 半球 r8 | 16px 圆 | 8px 圆 | 轮廓级，但"圆=普通帽" |
| 披风梯形 | 24×18px | 24px | 12px | 轮廓级，但"梯形=普通袍" |

**结论一句话**：v3 的辨识依赖"在形状内加 <3px 细节"（1px 帽带、1.5px 开衩、3×4 提灯、α0.22 淡光晕），这些细节在 32px 实渲染（尤其像素风无抗锯齿）下全部坍缩为噪点；而**外轮廓本身**（圆顶帽 + 梯形披风）与"任何一个戴帽小人"差异不足——颜色高对比只保证了"看得到白团"，没保证"看出是守夜人"。

### 1.3 三个具体失败机制

1. **加细节 ≠ 加辨识**：<2px 细节在 32px 帧（1080p 下 32 屏像素）中无法构成"特征"，只增加噪声。辨识度必须来自**外轮廓的形状节奏**（尖顶/宽檐/张开度），而非内部像素。
2. **轮廓与"普通小人"同构**：圆顶帽+梯形披风 ≈ 通用"戴帽小人"；与行尸（骷髅圆）、血犬（横条）、屠夫（梯形+角）相比，玩家缺少**独有轮廓锚点**（如尖顶、大檐、发光点）。
3. **描边冷青只增强"边缘感"不增强"形状"**：1.12 烘焙描边可见 ~1.6–1.8px，沿形状外缘走——形状本身没特征时，描边只是"给白团勾一圈彩边"，不携带"是什么"的信息。

### 1.4 顺带发现的潜在 C-1 边缘问题（v3 遗留）

- 玩家 pose1 帽冠 `arc(0,-7,8)` 顶 = **-15 → ×1.12 = -16.8，裁切 0.8px**（描边层顶部被 32×32 帧裁掉）。v2 校验只按 pose0（顶 -14）算，未校验 pose1。肉眼难见但属 C-1 纪律缺口，v3.5 一并修正（两 pose 顶统一 -14）。
- Boss 王冠尖 y=-60 → ×1.05 = -63，描边层裁切 3px（v2 §8 只校验了冠宝石 -56，未校验王冠尖 -60）。Boss 不在本波反馈内，**不修**，仅注记待快照（见 §6）。

## 2. v3.5 玩家强化方案（32×32 帧，中心 (0,0)，描边 1.12 → 内容坐标上限 ±14.29）

设计原则：**改轮廓而非加细节**。三条 P0 全部落在"外轮廓/大特征"层；P1 才是内部细节微调。所有颜色只用既有 token（`PALETTE.player` / `PALETTE.playerAccent` / `PALETTE.uiPaper` / `INK`），零新增色。

### P0-1 帽冠：圆顶 → 锥形尖顶（复杂度 低）

- **设定映射**：守夜人仍戴"帽"，但由"圆顶便帽"升级为"锥顶夜巡帽"——提灯夜巡人的经典帽型，轮廓辨识度远超圆顶。
- **实现**：替换 `playerShape` 中 `ctx.arc(0, pose===1?-7:-6, 8, Math.PI, 0)` 为尖顶多边形（两 pose 同顶，呼吸/摆动只体现在披风）：
  ```
  pose0 / pose1 相同：
  moveTo(-8, -6)      // 左帽肩
  lineTo(-6, -12.5)   // 左斜边
  lineTo(0, -14)      // 尖顶
  lineTo(6, -12.5)    // 右斜边
  lineTo(8, -6)       // 右帽肩
  close
  ```
- **可选**：两侧 `lineTo(-6,-12.5)` 改 `quadraticCurveTo(-6.5,-12, 0,-14)` 微凸，视觉更"帽"（语义相同，实现任选）。
- **边界**：顶 y=-14 → ×1.12 = **-15.68 ≤16 ✔**（margin 0.32，与 v2 最紧点同）。肩 x=±8 ✔。
- **token**：`PALETTE.player`。
- **注意**：此改动同时**修复 v3 pose1 的 0.8px 裁切**（旧 pose1 顶 -15 ×1.12 = -16.8 越界）。
- **16px 判定**：尖顶三角形在 16px 下缩为 ~4px 高的"尖角"，仍读"尖帽"——这是 P0-1 的核心价值。

### P0-2 帽檐：加宽 22px → 26px（复杂度 低）

- **设定映射**：宽檐夜巡帽 = 守夜人"遮风挡雨"的制式帽；加宽后帽檐成为**全身最宽特征**（26/32 = 81% 帧宽），与所有敌轮廓拉开。
- **实现**：`playerShape` 中 `fillRect(-11,-8,22,3)` → `fillRect(-13,-8,26,3)`（x±13, y -8..-5）。
- **边界**：x=±13 → ×1.12 = **±14.56 ≤16 ✔**（margin 1.44）；y=-8 → -8.96 ✔。
- **token**：`PALETTE.player`。
- **16px 判定**：宽檐缩为 13px 横条，与 8px 帽冠形成"大檐小冠"——比 v3 的"16px 圆+22px 檐"更接近 1:1.6 的帽型比例，轮廓节奏更明确。

### P0-3 提灯：放大 + 光晕强化（锚点特征，复杂度 中）

- **设定映射**：提灯 = 守夜人身份光源（也是玩家冷青 accent 的叙事化）。v3 灯太小（3×4px）太淡（α0.22），32px 下读作"旁边一个小蓝点"。
- **实现**：重写 `drawPlayerLantern`（仍为描边后正常比例绘制，不受 1.12；画序：**光晕 → 灯杆 → 灯体 → 灯芯**，光晕在最底层）：
  - 光晕外圈：`fillCircle(10.5, 0.5, 5.2)`，`PALETTE.playerAccent` α0.10（宽柔光）
  - 光晕内圈：`fillCircle(10.5, 0.5, 4.0)`，`PALETTE.playerAccent` α0.30（比 v3 r2.8/0.22 大且亮）
  - 灯杆：`fillRect(7, -6, 1.5, 5)`（x 7..8.5, y -6..-1），`PALETTE.uiPaper` α0.55（从帽檐右下缘伸出，避开加宽后的帽檐区）
  - 灯体：`fillRect(8.5, -2, 4, 5)`（x 8.5..12.5, y -2..3），`PALETTE.playerAccent` α0.95（4×5px，比 v3 3×4 大 67%）
  - 灯芯：`fillCircle(10.5, 0.5, 2.2)`，`PALETTE.playerAccent` α0.85
- **边界**：最右 x = 10.5+5.2 = **15.7 ≤16 ✔**（margin 0.3，**安全上限，勿加 r≥5.5**，会贴 16 裁切）；y ∈ [-4.7, 5.7] ✔；灯杆 y=-6 ✔。
- **token**：全部 `PALETTE.playerAccent`（同色不同 alpha 渐变），零新增。
- **16px 判定**：灯体 4×5→2×2.5、芯 r2.2→1.1、内圈 r4→2 —— 16px 下核心仍是"一个 2px 冷青亮点 + 1px 光晕"，读"发光点/灯"。

### P1-4 披风开衩：加深加宽（复杂度 低）

- **实现**：`playerShape` 三处 INK 开衩由 `1.5 宽 × 7 高`（pose0 y6..13）改为 `2 宽 × 9 高`（pose0 y4..13；pose1 y4..14）：
  ```
  pose0: fillRect(-8.5, 4, 2, 9) / fillRect(-1, 4, 2, 9) / fillRect(6.5, 4, 2, 9)
  pose1: fillRect(-8.5, 4, 2, 10) / fillRect(-1, 4, 2, 10) / fillRect(6.5, 4, 2, 10)  // 底 y=14 与披风 pose1 对齐
  ```
- **边界**：开衩为 INK 镂空，不改变外轮廓；x=±8.5 ✔。
- **token**：`INK`。
- **效果**：2px×9px 三衩在 32px 下呈三条纵向"袍摆分割"，强化"长袍"而非"裙子/帐篷"；16px 下为 1px 分割线，临界（可省略，见 §7 LOD）。

### P1-5 披风下摆加宽（pose0 12 → 13.5，复杂度 低）

- **实现**：pose0 披风 `(-9,-5)→(9,-5)→(12,13)→(-12,13)` → `(-9,-5)→(9,-5)→(13.5,13)→(-13.5,13)`。pose1 保持 ±14 **不动**（已是最紧 15.68）。
- **边界**：pose0 x=±13.5 → ×1.12 = **±15.12 ≤16 ✔**（margin 0.88）。
- **token**：`PALETTE.player`。
- **效果**：A 字形更张开，跑动剪影更"披风翻飞"。

### P1-6 帽带：保持 v3 原样（决策记录，不新增）

- v3 帽带 `fillRect(-10,-5,20,1)` playerAccent α0.75 已是帽檐下缘 1px 冷青横条。32px 下仅作色带提示、16px 丢失；零成本，**保留不增不删**。尖顶帽 + 宽檐后，帽带作为"帽檐底光"的语义更清楚。

### 描边决策：**不改色、不加粗**（P1 可选讨论，结论为否）

- 分析：若把描边放大层 1.12 → 1.16 加粗，内容坐标上限降为 16/1.16 = **13.79**，而披风 pose1 ±14、帽檐 ±13 均会越界（14×1.16=16.24 >16）——**加粗描边必须缩小轮廓，与 P0 目标相悖**。
- 冷青 = 玩家身份 token（art-bible §3 轮廓光纪律：描边禁止与背景同色系，冷青满足），不改色。
- 结论：描边维持 1.12 / 冷青不变；辨识度全部靠 P0 轮廓强化达成。

## 4. 普通敌 / Boss 顺带（R1 反馈主诉玩家；其余仅低成本 1 条）

### P1-A 屠夫·屠刀加宽 + 刃光提亮（复杂度 低）

- **背景**：屠夫是"厚血精英/集火目标"，屠刀 = 身份核心资产；v3 刀身仅 5px 宽（x 17..22）在 48px 帧中偏细。
- **实现**（`tankShape`，pose0/1 通用）：
  - 刀身：`moveTo(17,-5) → lineTo(22,-3) → lineTo(21,10) → lineTo(17,9)` → `lineTo(23,-3) / lineTo(22,10)`（右缘 +1px）
  - 刃光：`fillRect(21.5,-3.5,1,13)` → `fillRect(22.5,-3.5,1,13)`，α0.55 → 0.75
- **边界**：最右 x=23（刃光 22.5..23.5）≤ 24 ✔（帧半宽 24，无放大层）；y ∈ [-5,10] ✔。
- **token**：`PALETTE.enemyTank` / `PALETTE.uiPaper` / `INK`（既有）。
- **碰撞口径**：视觉至 x=23，碰撞半径 22——视觉略超碰撞 1px 可接受（同 v3 口径，不触碰 `ENEMIES.tank.radius`）。

### 行尸 / 血犬 / Boss：**本波不动**

- R1 反馈仅 E3 玩家一条，未点名普通敌/Boss；行尸/血犬在实渲染中骷髅头/横条剪影已可辨。**避免范围膨胀**。
- Boss 屏占比大（120px 帧 + ≥3x 体型），冠宝石/权杖可读，不动。

## 6. 移动端 LOD（≤16px 最小实体取舍）

- 当前相机 zoom=1、玩家 32px 基准，实渲染 32px（≥16px 达标）；本 LOD 规则覆盖"未来拉远/极小渲染"的最坏情形。
- **16px（×0.5）保留**（轮廓级，v3.5 的核心目标）：
  - 锥形帽尖（4px 高尖角）→ 读"尖帽"
  - 宽帽檐（13px 横条）→ 读"大檐帽"
  - 披风 A 形（12px 梯形）→ 读"长袍"
  - 提灯核心（2×2.5 冷青点 + 1px 光晕）→ 读"发光点/灯"
- **16px 省略**（亚像素，可在 `createCharactersAtlas` 内按 `cfg.isMobile` 跳过，**收敛位单一入口**，不散落 isMobile）：
  - 帽带 1px（0.5px 丢失）
  - 开衩 2px（1px 临界，可省略）
  - 提灯光晕外圈 r5.2 α0.10（16px 下无意义）
- **结论**：16px 下玩家靠「尖顶宽檐帽 + 冷青发光点」即可辨——正是 v3.5 的轮廓级强化目标；双端共享同一规格（asset-spec §4），LOD 只在绘制时按开关跳过。
