# 角色一致性 · 身份包

> 2026-09-10 · 调研与取舍。**执行以 `combat-identity-chengfa-v1.md` 为准**（2026-09-17 已升现行）。本文只留「为什么这样选」；合法工表若冲突听成法。  
> **第一例账本：** `identity-validate-vf1-plan-v1.md`

本地开源已经解决了风格限制和单张成本。没解决的是：**模型不会记住这个人。**  
从提示词 + 参考图抽下一张，永远是抽卡。把现在的人抽完，更新、新技能、新召唤仍会再抽一遍。

一致性的作者不是工作流参数，也不是「先给每人练一条 LoRA」。  
一致性的作者是 **一组锁文件（身份包）+ 只允许改清单上的东西（合法工）**。

---

## 0. 需求（主理人 2026-09-10 补全）

「胸甲正面、分层裙甲进 128/192」只是守誓者那一枪的例子。卡珊德拉、艾德蒙、薇奥莱等同理：每人一张零件表，降阶后还要能指。

| # | 锁 | 不锁 |
|---|---|---|
| ① 零件 | 每人 5–8 条外形锚，立绘 / 角色卡 / 战斗帧能对上 | 把守誓者的甲件写成全员验收词 |
| ② 动作之间 | 换动作只改姿势。低像素丢花纹、反光、布纹 **可以** | 同一人不同动作里，全身随机变形、换头、换衣、换甲 |
| ③ 面 | **最低：** 立绘、角色卡、战斗各帧是同一个人、同一套零件 | 战斗帧另开一套人。Q↔写实仍是另一套形象 |

③ 的完整愿望：立绘表情/动作、战斗外形象，也尽量还是这个人。那是包齐之后的扩面，不是现在的开工门槛。最低没过，不准谈表情包。

角色卡听立绘裁，不另抽一张人。战斗帧是降阶，不是换人。

## 1. 要稳住的不是「像」，是零件

每套形象先写 **零件表**（5–8 条，过目能指）。听立绘，不听色键，不听提示词形容词。

| 人 | 零件表示例（过目指，不是提示词作文） |
|---|---|
| 卡珊德拉 | 银白高马尾刃；酒红开襟大衣；前襟开胸 V；黑高领；胸前浅十字；细高跟 |
| 艾德蒙 | 疲倦成人脸；中等檐夜巡帽（不是猎巫塔帽）；破斗篷体量；髋侧一盏提灯 |
| 薇奥莱·守誓 | 长黑发（不是头巾）；披裙夜灰大面；银只胸/肩；胸前烛+焰；能指的眼 |
| 守誓者 | 闭面盔+盔缝当脸；大红羽；胸甲正面（中脊，不是罩袍遮胸）；分层金属裙甲；髋侧剑 |
| 魔化 / 加尔文 | 各跟自己已锁立绘写，未写不准开 1 层 |

零件表没写、或印戳对不上零件表，不准抽走、不准练 LoRA。错件炼进去，后面全是错件。

## 2. 身份包（一人一套形象一份）

| 层 | 文件 | 锁的是 | 没有就不准 |
|---|---|---|---|
| 0 形象套 | 剪影 · 立绘 · 色键 | 谁、色面积 | 开战斗 Queue |
| 1 单裁 | 立绘只裁此人 | 衣甲脸盔羽的零件 | 用双人成片硬切、用无脸色键当脸 |
| 1 印戳 | 带眼/盔缝硬色块全身，夜空底 | **零件表已在图里** | 入盒当进度、抽走、练 LoRA |
| 1 idle | 目标画布已过帧（她 128 / 他 192） | 战斗语言 + 同一套零件 | 在未过 idle 上长走/技能 |
| 2 可选 | 身份 LoRA（低权重，只挂出印戳的引擎） | 降低「同一引擎、下一张」的漂率 | 用失败印戳当训练料 |

卡珊德拉 / 艾德蒙：战斗包已过，本轮不重开。  
守誓：0 + 1 印戳 + 1 idle **已齐**；走 128 **已过（E2）**；技能未开。  
守誓者：0 齐，1 印戳 **零件未过**（胸甲/裙甲离立绘）。包不齐，不准 LoRA。  
魔化：0 齐；B-lo idle 128 过、未写 `frames/`。加尔文：0 近齐，战斗 1 未开。

立绘和战斗硬色块是 **同一份包的降阶**，不是两套人。Q 与写实横跳才是另一份包。

**验证期改听法：** 只认第一张图。剪影、色键从它派生，不另锁一套再回来打架。项目里三层独立过、零件对不上，是过程债，不是成法。方案有效之后，那些锁可以重做。

## 3. 合法工（只准这些）

每张开工卡必须写：**挂哪几个包文件、允许改什么、零件过目、两枪封顶。**  
漂了停，修包，不准加种子冒充新产线。

| 工 | 挂什么 | 只准改 | 废 |
|---|---|---|---|
| 印戳 | 单裁 | 压成硬色块、夜空；**零件不许换** | 罩袍吃胸甲、裙甲变布裙、换人、选人表 |
| 入盒 | 过关印戳 | 近邻进画布 | 硬切成片、脚本补甲、128 压 64 |
| 下一姿（C 轨） | **已过 idle + 过关印戳** | 姿势 / 相位。**2026-09-23 作者 = Qwen-Image-2.1 图片编辑**（满降噪按身份来源合法；指令写画面改变）。E1 的 Krea Identity Edit 留档。走循环作者 = Wan Animate 2（驱动视频；权重不在盘则停） | 零件变了、全身随机变形、站姿当走、低 denoise i2i 碰姿、独立 t2i |
| 补强 | 一张锁图（`GenerateImage` 或等价） | **只减清单脏**（沙漏、浅棚、背景眼） | 新衣服、新脸、当走条作者 |
| 少枪融景 | 已设计角色 + 场景底（`GenerateImage`） | **人进景、光跟景** | 角色抽卡、走条、战斗锁稿、预期多枪、触闭源限制 |
| 身份 LoRA | 单裁 + 过关印戳 + 已过战斗帧 | 只挂出印戳的引擎，低权重 | 失败枪进训练集；风格+身份炼一条；像素 LoRA 当作者 |

非法（这两周花掉的多半在这里）：提示词 t2i 当作者；六张独立抽签再混编；IPA+OpenPose 当身份锁；Qwen / Krea / WAI / H3 同 Queue；用 D2/色键重写立绘零件；同一条底连打 3 枪。

## 4. 以后更新怎么花钱（包齐之后）

| 需求 | 成本 | 做法 |
|---|---|---|
| 同一人、同一套、新走相 / 新技能 | **低** | 合法工「下一姿」。1–2 枪。零件漂了停，不盲抽 |
| 同一人、同一套、新召唤物待机 | 中（先齐那份包） | 先印戳零件过，再 idle，再才有「下一姿」 |
| 同一人、另一套（守誓↔魔化、新皮肤） | **高一次** | 形象套 D，新包。旧包不混 |
| 新人、同一风格帧 | 高一次 | 新包，成法照抄，不抄旧提示词碰运气 |
| 换风格（二次元↔写实、Q） | 高一次 | 新包。旧 LoRA 作废 |

「全部抽完再维护」会废，是因为抽完的是散张，不是包。  
包齐的角色，新增内容只开「下一姿」。开不出「下一姿」= 包坏了，回去修印戳，不是加预算继续抽。

## 5. LoRA 在方案里的位置

LoRA 是 **D 轨**（扩面 / 减漂），不是 B/C 的作者。详见 §9–§10。

上的条件（同时）：

1. 该包已有：单裁 + **零件过关的印戳** + 已过 idle。  
2. 后面帧多（走六相位、技能、或同包还要出第二套动作）。  
3. A+B 仍在同一引擎上漂零件或五官。

料只收过关文件。失败的 B-lo、选人表、硬切 96，不准进。  
只挂出印戳的引擎（守誓/守誓者印戳是 Krea，就不要把 WAI 立绘 LoRA 挂上去）。

第一份若要验证「更新不靠盲抽」：用 **守誓已齐的包** 走「下一姿」（走循环），需要时再给她上身份 LoRA。  
不要用守誓者现在的错甲印戳开第一份 LoRA。

## 6. 本机开源条还缺什么（不是再调 CFG）

条已经能锁：引擎、步数、CFG、输出进 `_park`。  
条还不能锁：零件表。零件在 **底图和过目清单** 里，不在 JSON 里。

要补的是工单，不是新模型：

1. 每包一份零件表（人读，过目指）。  
2. Queue 只接受「挂包文件 + 允许改 + 两枪」。  
3. 出图先对零件表，不对「好不好看」。  
4. 印戳未过关，入盒只作对照，不写进度。

抠图：浅棚/道具用合法工「补强」（Vf1 那种减法）。洪水脚本只去边，不当修甲。补强不改零件。

## 8. 社区里「几乎不漂」的案例，实际在用什么

2026 社区 / 视频站能反复创作、人几乎不换的，不是提示词抽卡。从结果反推，多半是下面几档（常叠两层）。对照：NWTIA 2026 综述、Civitai/Kohya 身份 LoRA 通识、Kling Omni Elements / Hailuo subject ref / Midjourney `--cref`/`--oref`。

| 档 | 是什么 | 锁得住 | 锁不住 | 和本项目 |
|---|---|---|---|---|
| 图生视频 / 一图动 | 一张锁图交给视频模型摇镜头 | 整段都是同一张像素 | 新胸甲、新步相、新画布 | 能做片头，当不了走循环作者 |
| 元素库 | Kling 四视图 Element、Hailuo 主体参考：先入库，提示词只写动作 | 已入库的脸和外形 | 库里没有的零件 | **商业版身份包。** 我们缺的是入库，不是提示词 |
| 身份 LoRA | 12–20 张**已经同一人**的图，Kohya / Ostris / Civitai Rapid，挂 0.6–1.0 | 脸、体型、标志物；姿/光/场可改 | 训练集里互相打架的甲；换底座引擎 | 社区生产默认。料必须先齐，不能拿 B-lo 炼 |
| 脸适配器 | InstantID / PuLID / IP-Adapter FaceID，零训练 | 脸（正/3/4 较好） | 裙甲、胸甲分件、硬色块 | 本机试过 IPA。只锁脸。叠 OpenPose 已禁当战斗作者 |
| 闭源参考 | Midjourney `--oref`、NovelAI 角色参考 | 插画脸 | 二次元/像素弱；换不了我们的 Krea/WAI 成法 | 不当战斗帧引擎 |

工作室稳的叠法（插画/短片，不是 128 棋子）：**低权重身份 LoRA + 脸适配器 + 姿态 ControlNet**。身份在 LoRA，脸再钉一层，姿另锁。这和「调 denoise 碰运气」不是一条路。

360° 轨道 Trick：视频模型绕已过的一张人转一圈，裁多角度静帧。圈内一致性是模型自己扛的。裁下来的图用来 **扩包或炼 LoRA**，不当成片。这是「一张过关印戳 → 15 张同意的料」的合法长法，不是盲抽。

他们「各种创作几乎不漂」，通常锁的是**脸还认得**。本项目的最低条更宽：立绘、角色卡、战斗各帧同一套零件；低像素丢细节可以，换件和乱变形不行。脸适配器会认脸、仍会发明另一身衣服——B-lo 已经演过。社区能搬的是 **先资产、后创作** 和 **同意的料才炼**；不能搬的是「上 InstantID 就当战斗作者」。

## 9. 办法核对（有效性 · 优缺 · 和 ①②③ 的适配）

评分只对**本项目需求**：① 零件能指 ② 动作之间不乱变形 ③ 立绘/卡/战斗帧同一人。不是对「网上好不好看」。

| 办法 | 社区有效性 | 优点 | 缺点 | ① 零件 | ② 动作不变形 | ③ 立绘↔卡↔战斗 | 本方案怎么用 |
|---|---|---|---|---|---|---|---|
| **身份包 / 元素库** | 高（Kling Element、Hailuo 主体、flowkit 都是这个） | 先入库再创作；更新不从零描述人 | 自己不画、不锁文件，库是空的 | 包里有才锁 | 不直接锁动作 | 卡裁自立绘 = 满分 | **留下，当总闸。** 不是模型 |
| **零件表 + 过目指** | 高（工艺，不是论文） | 和「像」切开；错件立刻停 | 要人写、人看 | **作者** | 过目用 | 过目用 | **留下。** JSON 锁不住这个 |
| **角色卡裁自立绘** | 满分 | 零抽卡、零漂 | 立绘错则卡错 | 跟立绘 | 无 | **③ 里最稳的一条** | **唯一合法出卡。** 不另抽 |
| **单裁 → 印戳 → 近邻入盒** | 本项目已验证（守誓 idle from-a） | 降阶后脸/锚点还在；不靠模型记人 | 印戳一步仍会换件（B-lo） | 印戳过了才有 | 不管动作 | **③ 战斗面的作者** | **留下，当降阶唯一作者。** 印戳不过关不准入盒当进度 |
| **已过 idle 低 denoise i2i** | 高（扩散常识；wave14 过高则洗烛） | 改的是同一张像素，最贴 ② | 大改姿要加骨架，否则拧 | 底对则零件还在 | **② 的主作者** | 从已过 idle 长出，不另认人 | **「下一姿」首选。** 不是 LoRA |
| **OpenPose 单独 + t2i** | 姿稳、人漂 | 步相能齐 | **不保护衣甲**（文档原意：OpenPose 只锁骨架） | 弱 | **弱（正是乱变形）** | 弱 | **非法。** 独立抽签再混编就是这个 |
| **OpenPose 叠在 idle 的 i2i 上**（不叠 IPA） | 中高：姿来自骨架，人来自底图像素 | 大改姿时少拧、少换件 | Krea 上 ControlNet 适配要另验；权重高会木偶 | 底对则还在 | **② 的辅，不是作者** | 跟 i2i | **允许试。** 和已禁的「IPA+OpenPose」不是同一叠 |
| **单人六相位一条** | 中：条内同一人；和已过 idle 仍可能是两个人 | 艾德蒙走过这条 | 条若 t2i 另抽，idle 对不上 | 条内有，跨条无 | 条内好，跨 idle 无 | 须从 idle 出发 | **合法，但底必须是已过 idle。** 禁止六张独立签 |
| **图生视频再抽帧** | 2025–26 像素精灵社区：走循环「直接出表」几乎失败，**一图动再抽帧**更稳（chongdashu 等） | 时间轴上同一个人 | 站姿摇视频容易假走（本项目 R8）；画法偏绘、要再入盒；脚底要对齐 | 底对则还在 | **时间一致好，步法语言另过目** | 只从已过 idle 出发 | **② 的备选，不是首选。** 过目仍听走姿，不听「会动就行」 |
| **身份 LoRA（12–20 张同意的图）** | 插画/短片生产默认，高 | 同引擎换场、换表情稳；更新便宜 | 料错则锁死错件；换引擎作废；不教硬色块 | 料对才有 | 减漂，**不替代 i2i** | 立绘扩面强；战斗要另炼战斗料 | **第 2 层。** 立绘表情走 WAI 料；战斗走 Krea 料。禁止一条炼两轨 |
| **脸适配器 InstantID / PuLID / IPA** | 锁脸高，锁衣低 | 零训练 | 认脸发明另一身衣服；本机 IPA 已漂 | **不适配 ①** | 不适配 ② | 立绘脸可辅，战斗不当作者 | **不当作者。** 不叠 OpenPose 当走条 |
| **ControlNet Reference-Only** | 不稳（社区评价有时有、有时走） | 想锁衣服 | 不可复现当产线 | 赌 | 赌 | 赌 | **不进合法工** |
| **闭源 --cref / --oref** | 写实插画脸中高 | 省事 | 换不了 Krea/WAI 成法；像素弱 | 弱 | 弱 | 卡/战斗搬不过来 | **不用** |
| **360° 轨道扩料** | 中：扩多角度同意料 | 一张过关图变 12+ 张，少盲抽 | 视频瑕疵；不当成片 | 底对才有 | 无 | 给 LoRA 备料 | **合法扩包。** 不当战斗帧 |
| **像素吸附 / 中位色 / 量化当作者** | 表面对齐好看 | 网格齐 | 本项目 R19：硬切/BOX/中位色 = 废；丢脸灯 | 会吃零件 | 会另变一套 | 和已过 128 打架 | **禁止当作者。** 入盒只近邻 |
| **GenerateImage 减法补强** | 本项目 Vf1 已验证 | 去沙漏/浅棚，人还在 | 无种子槽；当 64 作者必漂 | 只减不增才有 | 无 | 只修锁图 | **留下，只减清单脏** |
| **GenerateImage 少枪融景** | E5 tombstone / pew **过**并进 D | 人+景+光一体，比本机 Identity Edit 强 | 无种子；场景画法会二次元化 | 人已设计、极少枪才有 | 无 | 图鉴 / 剧情立绘级场景 | **留下。过关成片可进同衣套 D。禁止用本接口抽角色喂 D。姿势优化只记想法** |

结论：网上「几乎不漂」的叠法（LoRA+脸锁+OpenPose）是为**插画换场**优化的。你们最痛的是 **② 动作之间不换件**，社区里更稳的是 **同一张已过像素的变换**（低 denoise i2i，必要时只加骨架），不是再认一次人。LoRA 适合 **③ 扩面**（立绘表情、战斗外）和包齐后减漂，不适合当第一层身份，更不适合拿错印戳开炼。

## 10. 修正后的叠法（分轨，仍待过）

上一版容易读成「包 + 炼 LoRA 就齐了」。核对后改成四轨。轨不混作者。

| 轨 | 解决 | 作者 | 不上 |
|---|---|---|---|
| **A 入库** | 总闸 | 形象套 + 零件表 + 单裁 | 空包抽卡 |

## 11. 「多套」指什么（防读成一人多套认人方案）

可以理解为：同一角色要面对不同**使用面**，所以包里会有几份派生素材，用工也不同。  
不可以理解为：同一角色准备三套 LoRA、再加 IPA、再加 I2V，谁稳用谁。那是把作者叠打架，正是这两周的浪费。

| 真的要多份的 | 只要一份的 |
|---|---|
| **形象套**：守誓 / 魔化 / 新皮肤 = 另一份包（零件表另写） | 同一套里的「认人」：立绘单裁 + 零件表只锁一次 |
| **派生**：立绘、角色卡（裁）、战斗印戳、已过 idle、由 idle 长出的走/技能 | 同一套里的引擎：出印戳用谁，后面就挂谁，不混 Queue |
| **工**：B 降阶、C 动作、D 扩面，各用各的作者 | 角色卡、战斗帧不另抽一张人 |

薇奥莱因此是两份包（守誓一份、魔化一份），不是一份方案打天下。每一份包内部：卡裁自立绘，战斗降阶自立绘，动作来自已过 idle。方案多，是因为面不同；人只有一份。
