# 《血月守夜》版本规范（Versioning）

> 版本 v0.1 · 作者：路远行（发布运营管理）· TASK-29 · 遵循 [SemVer](https://semver.org/lang/zh-CN/)

## 1. 结论：Demo 验收发布用 0.2.0，不用 1.0.0

**结论：当前 0.1.0 → Demo 验收发布升 **0.2.0**，不升 1.0.0。**

理由（三点）：

1. **定位诚实**：本作是"垂直切片 Demo"（concept §5 目标：先验证好玩、产出概念基线），并非完整产品。SemVer 中 1.0.0 表示"首个稳定/完整公开发布"，会向玩家与渠道释放"正式版"信号——Demo 阶段占用 1.0.0 会透支首发语义。
2. **0.x 兼容性空间**：0.x 允许破坏性变更。Demo → 完整产品必然大改（新角色/超武/局外解锁/设置系统），停留在 0.x 可避免频繁升 1.x 又回退的混乱。
3. **里程碑对应**：0.1.0 = 内部开发基线（现版本，未发布）→ 0.2.0 = 可验收 Demo（本任务目标）→ 1.0.0 = 完整产品首发。0.1→0.2 的 minor 升级恰好承载"可玩切片 → 可验收 Demo"的量级差异。

**例外**：若渠道/平台强制要求 1.0.0 首发，再按渠道要求升版并记录豁免（对应 release-checklist G9）。

## 2. 版本规划（0.x → 1.0 里程碑）

| 版本 | 节点 | 内容 |
|---|---|---|
| 0.1.0 | 当前（内部） | 垂直切片开发基线：E1–E4 完成、292 单测绿、音频/剪影 v2/埋点就绪；未发布 |
| **0.2.0** | **R3 通过后** | **Demo 验收发布**：release-checklist G1~G10 全过 + WorkBuddy 轻应用部署 |
| 0.3.x–0.9.x | 内容扩展 | 新角色/超武/局外解锁/设置系统（Standard 级可访问性）；每大特性 minor+1，修 bug 用 patch |
| 1.0.0 | 完整产品首发 | 商业化/云存档/成就等正式能力就绪，渠道首发 |

## 3. 版本号与标签规则

- **唯一权威来源**：package.json `version`；发布前核对构建产物与部署备注一致（G8）。
- **git tag**：`v0.2.0`（发布成功后打）；hotfix 用 patch 如 `v0.2.1`。
- **变更日志**：每版本对应 CHANGELOG.md 一节（Keep a Changelog 格式），字符串冻结后变更须同步日志。
- **发布动作**：升版 → build → 部署 → 验证 → 打 tag（详见 release-checklist §2）。
