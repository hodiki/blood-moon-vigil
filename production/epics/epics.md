- **依赖**：—｜**估算**：0.5d｜**对应**：ARCH-§1/§7 步骤 1、RV-C3 / 放行 5
- **验收断言（可机械判定）**：
  1. `npm run typecheck` 退出码 0（tsconfig strict + noUncheckedIndexedAccess，ARCH-§1.4）。
  2. `npm run build` 成功产出（`base: './'` 生效）。

### E1-S2 · core 基础设施（事件 / 状态 / 时间 / 池）
- **依赖**：E1-S1｜**估算**：1d｜**对应**：ARCH-§3.1/§3.2/§3.3/§3.4/§3.5、CM-§5 状态联动
- **验收断言（纯逻辑单测）**：
  1. `GameState` 四态 RUNNING/LEVEL_UP/PAUSED/GAMEOVER：合法转换生效、非法转换被拒绝、`onChange` 回调触发（CM-§5 联动表为最终状态矩阵）。
  2. `clampDelta(80ms) = 0.05s`（上限 50ms）；帧间隔 >250ms 时按 250ms 处理（ARCH-§3.5 极端掉帧保护）。
  3. `ObjectPools`：acquire 达 `maxSize` 时按既定策略处理（返回 null 或回收最早，实现选定后断言该策略）；release 后复用、字段已重置；`eachActive` 只遍历 active（ARCH-§3.2 接口）。
  4. `GameEvents` emit/on/off 正常；事件名集中常量、无字符串魔法值（ARCH-§3.4 约定）。
- **双端注意点**：纯逻辑无差异；`GameState.set()` 集中副作用（physics/tweens/粒子/输入）为后续 PAUSED/LEVEL_UP 双端冻结打底（CM-§5）。

### E1-S3 · RuntimeConfig 平台检测 + 双端配置

- **验收断言（配置快照断言）**：

  2. 移动配置：`maxEnemies=250`、`maxParticles=100`、`maxGems=200`、`designWidth=720`、`designHeight=1280`、`outlineEnabled=false`、`screenShake=false`、`edgeWarning=false`、`spawnRing=[500,800]`（ARCH-§4.2 + RV-C2）。

### E1-S5 · 移动端虚拟摇杆

## 2. E2 战斗闭环（架构步骤 4–5）

**范围**：伤害结算、3 种普通敌人、三武器（飞弹/环绕球/冲击波）、敌潮生成器。
**对应系统**：S8 / S4 / S3 / S5。
**完成定义（DoD）**：
1. 三武器全自动触发，无任何手动瞄准/攻击（W8-1 / C9-支柱 1）。
2. 3 种敌人面板与 enemies §③ 表一致；接触伤害 + 无敌帧正确（E8-1/2）。
3. 生成器按 `budget(t)` 公式运行 20 分钟压力曲线，同屏 400/250 无溢出（S8-1/5、E8-5）。
4. 三武器数值与升级成长接口就绪（E3 可直接写回）。

> **顺序说明（对 system-map §3 字面顺序的工程修正）**：system-map P0 顺序写作"武器→伤害→敌人→生成器"，但武器命中/追踪/秒杀断言（W8-2）需要真实敌人目标，生成器也需要敌人面板定稿（system-map §4.2 自述"敌人须先定稿"）。故 E2 内调整为：**伤害结算 → 敌人 → 飞弹 → 生成器**，既满足依赖又不违背闭环链（S8→S4→S3→S5 的依赖箭头不变）。

### E2-S1 · 伤害结算模块（倍率 / 无敌帧 / 死亡分发）
- **依赖**：E1-S6｜**估算**：1d｜**对应**：ARCH-§3.4 事件表、S8、RV-C7
- **验收断言**：
  1. 命中伤害 = 武器基础伤害 × 总倍率；初始倍率 1.0；总倍率 = 1 + 0.04×等级 + Σ升级池加成（加法叠加，U8-§③ / W8 校验）。
  2. 无敌帧 0.5s：同帧多敌接触只扣 1 次（时间戳比较，E8-§⑥.3 / RV-C7）。
  3. 死亡分发：HP≤0 → 从碰撞列表移除 → `emit('enemy:killed', { enemyType, xp, x, y })`（E8-§⑥.4、ARCH-§3.4 事件表）。
  4. 玩家 HP≤0 → `emit('player:died')`（ARCH-§3.4）。
- **双端注意点**：纯逻辑共用；为 E3 吸血/伤害强化预留倍率聚合入口（U8 第 8/10 项）。

### E2-S2 · 敌人实体 + 3 种面板（僵尸 / 疾行 / 厚血）
- **依赖**：E2-S1｜**估算**：1d｜**对应**：S4、E8-§③/§⑧、RV-C1（描边纪律）
- **验收断言**：
  1. 面板与 enemies §③ 表完全一致（埋点断言）：僵尸 12HP/55px/s/10 伤/1.0s/14px/1 经验；疾行 10HP/150px/s/8 伤/0.8s/12px/2 经验；厚血 600HP/35px/s/20 伤/1.5s/22px/15 经验（E8-1）。
  2. AI：向玩家直线移动；敌人互不碰撞（允许重叠，E8-§⑥.2 / RV-C1 物理对数控制）。
  3. 接触伤害按攻击间隔循环 + 玩家无敌帧 0.5s 合并（E8-2）。
  4. 厚血怪死亡掉 15 经验（3 倍）（E8-3）。
  5. 普通 3 敌共用一池（classType+maxSize，ARCH-§3.3）；**普通敌无 FX.Outline**（RV-C1 / 放行 1）。
- **双端注意点**：池上限桌面 400/移动 250（E8-5）；移动端死亡粒子 8 粒、最小实体 ≥16px（由 720×1280 保证，RV-C2）；厚血怪常显血条 48×6px（E8-§③）。

### E2-S3 · 自动飞弹「血月猎手」
- **依赖**：E2-S2｜**估算**：1d｜**对应**：S3、W8-§③/§⑥/§⑧
- **验收断言**：
  1. 冷却 1.2s 自动触发；命中伤害 12 × 倍率；1 发秒杀僵尸（12 ≥ 12HP）（W8-2）。
  2. 追踪最近敌人 400px/s、飞行寿命 3s（行程 1200px > 出生环带 900px，RV-N9 可达性）。
  3. 无目标不发射；目标中途死亡立即重寻、无目标原地消散（W8-§⑥.1/2）。
  4. 同屏 ≤8 发：达上限跳过本冷却、不积压、不报错（W8-4）。
  5. 升级接口：飞弹分裂（+1 次级弹 ×0.6 伤、可 2 次）/ 穿透 1 次（W8-3，E3 写回）。
- **双端注意点**：池上限 8 双端一致（ARCH-§3.2）；移动端拖尾简化为 1 短条（W8-§⑦）。

### E2-S4 · 敌潮生成器（预算 / 阶段 / 上限）
- **依赖**：E2-S3｜**估算**：1d｜**对应**：S5、S8-§③/§⑧、ARCH-§6 预算表 #1
- **验收断言**：
  1. `budget(t) = 1.2 × (1 + 2.5×t/1200) × (1 + 0.4×sin(2πt/75))` 与压力曲线表一致（埋点断言生成速率，S8-1）。
  2. 构成权重按阶段表：0–3min 95/5/0、3–8min 80/17/3（每 20s 保底 1 厚血）、8–15min 65/28/7、15–20min 50/35/15（S8-1）。
  3. 出生环带：桌面 600–900px / 移动 500–800px 随机角度，屏外生成（S8-§③、ARCH-§4.2）。
  4. 同屏上限生效：桌面 400/移动 250，达上限暂停生成 2s 后重试、不丢弃预算（S8-5、E8-5、ARCH-§3.3 池满策略）。
  5. 帧率无关：预算按秒累加、掉帧不跳怪（S8-§⑥.5 / ARCH-§6 预算表 #10）。
  6. 20:00 预留 Boss 收束钩子（停止生成 + 清场接口，E4-S3 复用）。
- **双端注意点**：同屏上限参数化是**唯一数值差异**（S8-§⑦）；移动端关闭边缘红光（省性能）。

### E2-S5 · 护体环绕球「守夜之环」
- **依赖**：E2-S3｜**估算**：0.5d｜**对应**：S3、W8-§③/§⑤/§⑧
- **验收断言**：
  1. 基础 3 颗、环绕半径 80px、转速 240°/s（1.5s/圈）；伤害 8/次命中（W8-§③）。
