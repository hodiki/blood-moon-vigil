## 1. 步骤 3：`y` 到底是什么语义（本任务的核心判定）

### 1.1 结论

**`y` 是「画布锚点中心」，不是「地面/脚底」。** 全仓玩家的地面线 = `y + 63.5`（128 画布）。

三条独立证据：

**① 代码事实**：`Player extends Phaser.Physics.Arcade.Sprite`（`src/player/player.ts:42`）用 `super()` 默认 `origin(0.5, 0.5)`。全仓 `setOrigin` 只有 3 处命中，无一作用于角色/敌人——`float-text`（文字）、`summon-weapons`（光束）、`oathkeeper-view.ts:103`（**注释**）。敌人的 `body.setCircle` 也一律配默认锚点。

**② 有人已经把这件事写成了常量**（`src/weapons/companion/oathkeeper-view.ts:80-118`，守誓者 192 画布那批）：

```
PLAYER_FOOT_OFFSET = 63.5   // 「玩家（128 画布英雄）脚底在锚点下方的世界 px」
地面线取「最低不透明像素行的中心」= footY + 0.5
127.5 − 64 = 63.5（scale 1）
为什么不用 setOrigin(0.5, 0.9974)：全仓角色/敌人一律默认 origin（player.ts 也是），
集中在一处用常量偏移，比「给一个精灵改 origin」更不容易被后人误读成特例。
```

**③ 运行时实测**（见 §2 与 `四角色地线.json`）：128 画布英雄 `displayOriginY = 64`、脚底屏幕行 = `y + 63`（128 画布原点行 127 → 603 − 540 = 63，四舍五入自 63.5）。

### 1.2 影子 / 血条 / 闪白挂在哪（决定 P1 是否真的"更省事"）

| 项 | 实测结论 |
|---|---|
| 影子 | **玩家没有影子精灵**。全仓 `shadow` 只命中 CSS `box-shadow` 与 `enemy-shadowwolf`（狼种帧名）。⇒ 不存在"影子跟着沉"的问题 |
| 血条 | **DOM HUD**（`src/ui/hud.ts`，订阅 `hp:changed`），不挂在 sprite 上，与锚点无关 |
| 受击闪白 | 玩家 sprite **无 tint 闪烁**（`setTint` 全在 FX 粒子/状态标记/关卡危险区上）。`immune-feedback` 走 alpha，与位置无关 |
| 相机 | `PlayScene.ts:702` `startFollow(player, true, 0.12, 0.12)` —— 跟的是 `player.x/y`，与锚点无关 |

⇒ 交付单"若他还有影子/血条/闪白挂在同一 sprite 上，P1 更省事"的前提**在这里不成立**：没有任何东西挂在 sprite 上，P1 省不了事，反而因为**锚点错位 63px** 让整个角色（含碰撞体）飞到半空。

### 1.3 为什么交付单的两个方案都不能直接用

| 方案 | 字面做法 | 实算结果（实测） |
|---|---|---|
| **P1** | `setOrigin(0.5, 159/160)` | 脚落在 `y` 本身 ⇒ 比同 y 的薇奥莱**高 63px**（**Δ = −63px**）。人整个悬空，比不改更糟 |
| **P2** | 居中锚点 + "y 统一 +16 偏移" | 方向反了。要补偿必须 **−16**；且 `player.y` 是全仓玩法权威值（索敌/拾取/相机/边界 clamp/狂化光环 30+ 处），改它等于改玩法 |
| **实采（本报告）** | `originY = (H − 64)/H` → 160 = **0.6** | 脚底 = `y + 63.5`，与 128 画布英雄**同一个数**。Δ = 0 |

一句话：**160 画布要下沉 16px 才对，不是抬 63px。** 交付单把"128 画布脚在 y+63.5"误当成"脚在 y"了。

### 1.4 落地做法（两行代码，只作用于"画布 > 128"的玩家）

`src/fx/combat-display-scale.ts` 新增两个纯函数（可单测）：

```ts
PLAYER_FOOT_OFFSET   = 63.5        // 与 oathkeeper-view.ts 同口径
groundAnchorOriginY(H) = H <= 128 ? 0.5 : (H − 0.5 − 63.5) / H   // 160 → 0.6，128 → 0.5（恒等）
groundAnchorBodyOffset(W, displayOriginY)                          // 把 Arcade Body 补回 128 画布位置
```

`src/player/player.ts` 构造器内（`applyCombatDisplayScale` 之后）：

```ts
const anchorY = groundAnchorOriginY(this.frame.height);
if (anchorY !== GROUND_CENTER_ORIGIN) {        // 128 及以下 → 不进入 ⇒ 零影响
  this.setOrigin(0.5, anchorY);
  const off = groundAnchorBodyOffset(this.frame.width, this.displayOriginY);
  body.setOffset(off.x, off.y);                // 160：offset = (16, 32)
}
```

**为什么要补 body offset**：Phaser 的 `Body.updateFromGameObject` 每帧按
`body.topLeft = sprite.x/y − displayOrigin + offset` 推导碰撞体（`node_modules/phaser/src/physics/arcade/Body.js:1054-1064`），
所以**画布变大**和**改 originY** 都会把碰撞体推走：

| | body 左上角（相对 player.x/y） | 接触判定圆心（r=14） |
|---|---|---|
| 128 画布 · origin 0.5（全部现有英雄） | (−64, −64) | (−50, −50) |
| 160 画布 · origin 0.5（只换图不改码） | (−80, −80) ← 上移 16 | (−66, −66) |
| 160 画布 · origin 0.6（只改锚点） | (−80, **−96**) ← 上移 32 | (−66, −82) |
| **160 画布 · origin 0.6 + offset(16,32)（本次）** | **(−64, −64)** ✅ | **(−50, −50)** ✅ |

⇒ 玩家–敌人接触伤害（`PlayScene.ts:650` `physics.add.overlap`）与玩家–障碍 AABB（`PlayScene.ts:642`）的几何**与换图前逐像素一致**，也与其它英雄一致。换图因此是**纯视觉**改动。

> 附带获得的一致性：狂化 `scale 1.4` 时脚底 = `y + 63.5 × 1.4`，与 128 画布英雄**同一个公式**（实测 §5.3：629 vs 628，Δ ≤ 1）；若用居中锚点会是 `y + 79.5 × 1.4`，狂化时比别人多陷 23px。
