## 0. 结论先行（TL;DR）

1. **交付单的"美术已就绪"只在"源 PNG"这一层成立。** 主理人核出的 ①~⑤ 我逐层复核**全部成立**，且**另外核出 5 层新缺口**（⑥ 帧规格表静默吞掉 `-attack-a`、⑦ 交付集单测门禁、⑧ 工作区脏且与在途批次撞同一批文件、⑨ `assets/raw/` 旧图会被 `process.mjs` 反向覆盖新 192 帧、⑩ 脚底线）。**照交付单写那 35 行，精灵一定不出现** —— 不是因为代码写错，而是**这条链路上没有任何一环会报错**：帧名不存在就静默跳过，坐标不对就默默站在坑里。
2. **`pack.mjs` 是全量重打包，但重打不会改变任何已过角色的外观。** 实测：现有 `characters.json` 与 `assets/frames/` **116/116 帧尺寸完全一致**，重打只动**图集内坐标**（104/116 帧坐标会变），像素与帧尺寸不变，Phaser 按帧名取帧 → 已过角色无感。**容量也不会溢出**（2048² 画布用高 816px → 992px）。
3. **`summon-moonwolf` 无法复用** —— 它和守誓者一样**只有注册表、没有任何精灵创建代码**（`grep summon-moonwolf src/` 仅命中 `frame-registry.ts:61`）。仓库里**不存在**"召唤物精灵"的既有实现，这是第一份。
4. **撕咬信号已经存在，不用加事件总线**：`tickBite` 返回 `dealt`，`OathkeeperRuntime.update()` 原样返回，只是 `PlayScene.ts:1019` 把返回值**丢掉了**。接一个变量即可。
5. **交付单漏了脚底线**：直接 `sprite.y = state.y` 会让他的脚**沉到地面下 32px**（算式见 §3.4）。另有第四处"照抄会翻车"：不判 `isEnabled` 会给**每个角色**都画一个骑士（`createOathkeeperState` 默认 `phase='companion'`）。
6. **`-v` 与 idle 是同一个文件**（md5 相同）→ 交付单说的"1px 呼吸"是**逐像素零差异**，播与不播完全一样。
7. **白捡的升级**：`x192v2/` 里躺着一张 `summon-oathkeeper-attack-b.png`（同基准入盒、脚底 191、头心 96.5，实测）→ 劈砍可以从"单帧闪一下"变成**两帧真挥砍**，零美术成本。
8. 工程侧合计 **3~5 人日**（关键路径 A→B→C→E→F ≈ 2.25~3.5；D 可并行）。

## 2. 实施批次拆分

> 原则：**每批都能独立判断"成了没有"**，且每批的回滚命令**文件级**。因为工作区不干净（§1⑧），**严禁宽域回滚**（`git checkout .` / `git checkout -- assets` / `git stash` 一律不许）——会把在途 152 个改动一起卷走。
> **批次 0 是硬前置**：先让工作区干净（commit 或在途批次自建分支提交），否则批次 C 的回滚会把在途加尔文批次的图集产物一起丢掉。

### 批次 C · 重打包 characters（**风险最高的一批**）
- **动作**：**只打一个图集**：`node tools/asset-pipeline/pack.mjs characters`
  - ⚠ **绝对不要**跑裸 `node pack.mjs`：它会重打全部 5 个图集（effects/ui/ui-portraits/ui-slots）并重写 `assets/preview-64-row.png`，把无关图集的位图也换掉，回滚面放大 5 倍。
  - 它会顺带重写 `assets/atlas/pivots.json`（读 `assets/report.json`，不重算指标）。
- **`pack.mjs` 是全量还是增量？→ 全量。** `packAtlas()` 每次 `readdirSync(assets/frames/)` 重收集、重新 `binpack`、整块重写 JSON + PNG，**没有任何增量/缓存**。
- **会不会影响已过角色帧？→ 外观不会，坐标会。** 实测结论（我把 `binpack` 逐行复刻后用真实帧清单跑了一遍）：

  | 场景 | 帧数 | 画布 | 用到高度 | 既有帧坐标变化 |
  |---|---|---|---|---|
  | A 现状 | 116 | 2048² | 816 | — |
  | **B 目标**（idle/-v 升 192 + 新增 5 张） | 121 | **2048²** | **992** | **104/116** |
  | C 连墓碑也升 192（未来批） | 121 | 2048² | 992 | — |

  - ✅ **不会溢出 2048 上限**（`binpack` 的 `throw '图集超过 2048px 上限'` 不会触发，余量 1056px 高）。
  - ✅ **帧尺寸/pixels 不变**：现图集 116 帧尺寸与 `assets/frames/` **116/116 一致**，重打是幂等的（唯一进入的是 5 个新帧 + 2 个升档帧）。
  - ⚠️ **`characters.png` 的二进制会变**（重合成 + 重压缩），JSON 里 104 帧的 x/y 会变。Phaser 按**帧名**取帧 → 功能无影响；**但任何"硬编码图集坐标"的脚本/快照会红**（本仓实测无此类消费方）。

- **防护措施（四条，缺一不可）**：
  1. **先备份三件套**：`cp assets/atlas/characters.{png,json} assets/atlas/pivots.json /tmp/oath-bak/`（比 git 快且不受脏工作区影响）
  2. **前后做帧名集合 diff**：打包后比对新旧 JSON 的 `filename` 集合，**只允许 `+= 5`，不允许 `-=`**（`-=` 说明有问题帧被吞）
  3. **进场目视复核 3 个既有角色 + 2 个敌种**（加尔文 / 薇奥莱 / 卡珊德拉 / 僵尸 / 石甲狼）：位置/大小/朝向与打包前一致。这是"已过批次没被动"的唯一可信判据（截图对比，不看 JSON）
  4. **不提交 `assets/preview-64-row.png`**（本轮不生成，若已有改动请 `git checkout` 回去）

- **验收判据**：
  1. `python -c "import json;d=json.load(open('assets/atlas/characters.json'));print(len(d['frames']),d['meta']['size'])"` → **121 2048×2048**
  2. JSON 内含 `summon-oathkeeper-walk-a..d` + `summon-oathkeeper-attack-a`，且 `summon-oathkeeper` 的 `w/h` = 192
  3. `node tools/asset-pipeline/pack.mjs --check characters` → `2048x2048 ≤2048 ✔ | JSON 数组格式 ✔ | 帧数 121`
  4. 上述防护 3 的 5 个实体目视一致
- **回滚**：`cp /tmp/oath-bak/* assets/atlas/`（**优先**）或 `git checkout assets/atlas/characters.json assets/atlas/characters.png assets/atlas/pivots.json`

## 3. 技术设计（结构与取舍，不写完整代码）

### 3.1 两文件分层

```ts
// src/weapons/companion/oathkeeper-view-state.ts —— 纯函数，零 Phaser
export type OathkeeperVisual = 'idle' | 'walk' | 'attack' | 'tombstone' | 'hidden';

export interface OathkeeperViewInput {

  dt: number;                  // 秒
  biteDealt: number;           // 本帧 runtime.update() 返回值
  playerDx: number;            // player.x - state.x

  attackElapsedMs: number;     // 回写量：劈砍计时

export interface OathkeeperViewOutput {
  state: OathkeeperVisual;
  frame: string;               // 'summon-oathkeeper' | '-walk-a..d' | '-attack-a' | '-tombstone'
  flipX: boolean;
  yOffset: number;             // 脚底对齐常量（-32）
  walkElapsedMs: number;
  attackElapsedMs: number;
  teleported: boolean;         // 本帧是否被判为瞬移（调试/遥测用）
```

```ts
// src/weapons/companion/oathkeeper-view.ts —— 薄壳，只读写精灵
export class OathkeeperView {
  constructor(scene: Phaser.Scene);
  /** 每帧：读 rt.state（轮询）→ 纯函数决策 → 写 sprite */
  sync(rt: OathkeeperRuntime, player: { x: number; y: number }, dt: number, biteDealt: number): void;
  destroy(): void;

```

**取舍说明**
- 纯模块只在 `resolveOathkeeperView` 里做**状态判定与帧选择**，不持有计时以外的状态；`frame` 用**手动 `setTexture` 步进**，**不起 Phaser anim**。理由：`anim.ts:139-163` 已经自动为基帧建了 **6fps** 的 `summon-oathkeeper-move`，若 view 再 `play()` 同名 key 会打架；手动步进把 330ms 完全握在自己手里，也没有"单帧动作用 anim 播"这种别扭。
- **不加 `setPhase()` 公开方法**：相位是**只读事实**，view 不该有写入口。构造函数 + `sync()` + `destroy()` 三个就够——多一个 `setPhase()` 就多一处"谁能改相位"的歧义。

### 3.2 三态判定源（含 12 条单测判据）

| 判定 | 源 | 规则 |
|---|---|---|
| 可见性 | `enabled && phase !== 'gone'` | **`enabled` 必须在最前面**（`createOathkeeperState` 默认 `phase='companion'`，不判 enabled 会给所有角色画骑士） |
| 速度 | 本帧 `hypot(dx,dy)/dt` | 阈值 **5 px/s**（与 `anim.ts:166-170` 的 `isMoving` 同口径） |
| 瞬移护栏 | `hypot(dx,dy) > 400` | 视为**瞬移**（复活/重召唤/首次入场），本帧不判 move ≤ 直接 idle。不加这条，复活瞬间会抽 1 帧 walk |
| attack | `biteDealt > 0` → `attackElapsedMs = 0` | **单帧档**：`-attack-a` 保持 **150ms** 后回落。**两帧档（推荐，若批次 B 取了 attack-b）**：`-attack-a` 100ms → `-attack-b` 100ms → 回落（共 200ms，仍在 1.0s 撕咬间隔内，不会叠） |
| walk 帧 | `walkElapsedMs += dt*1000`，每 **330ms** 进一帧 | 序 `a→b→c→d→a`；离开 move 时**归零**（避免下次起步从 c 帧开始，看起来像崴脚） |
| flipX | `playerDx` 死区 **8px**（复用 `anim.ts:17` 的 `FACING_DEADZONE`） | `>8` → `false`（原图朝右）；`<-8` → `true`；死区内**保持上一帧朝向**（防站在正上方时抖动翻面） |
| 不旋转 | — | `setRotation(0)` 一次，永不改（斜 30° 已画进帧、劈砍拖影也在图里） |

**优先级铁律**：`tombstone / hidden`（相位）> `attack`（撕咬是个瞬时动作，压过 idle/walk）> `walk` > `idle`。
> 为什么两帧档值得做：单帧 150ms 只是"闪一下"，在 1.0s 的撕咬间隔里读不出"他在砍谁"；而 attack-a→b 是**同一动作的起手与收势**，两帧各 100ms 是能读出"挥"的最短配置，且**不需要任何美术产出**（图已在仓，见 §1 额外机会）。判定方法同 R5：录 5 秒，能看出"抬手→落下"就成。

**单测用例（批次 D 的验收内容）**
1. `enabled=false` → `hidden`（任何 phase） 2. `phase='gone'` → `hidden` 3. `phase='tombstone'` → `tombstone`、frame=`-tombstone`
4. 静止（speed=0）→ `idle`、frame=`summon-oathkeeper` 5. speed=6 → `walk`、首帧 `-walk-a`
6. 累加 330ms → `-walk-b`；1320ms → 回 `-walk-a`（4 帧整圈） 7. 从 walk 切 idle 再切回 → 重新从 `-walk-a` 起（累加器归零）
8. `biteDealt=8` → `attack`、frame=`-attack-a`；150ms 后回 `walk`/`idle` 9. attack 中变 `tombstone` → 立刻 `tombstone`（相位优先）
10. `playerDx=+20` → flipX=false；`-20` → true；`+3`（死区内）→ 保持上一值 11. `dx=1000`（瞬移）→ `teleported=true` 且不当 move 12. `dt=0` 不产生 NaN、不推进计时

### 3.3 如何取 `state.x/y` 与 `phase`：轮询 vs 事件

**选轮询，理由三条：**
1. **单消费者**：只有 view 一个读方，事件总线（`GameEvents`）在这里是纯开销，还引入订阅泄漏风险（`scene.restart` 复用实例）。
2. **相位是状态不是事件**：`tombstone→companion` 的转换点散在 `revive/convertHealToRevive/tickResummon/tickTombstone` 四处，发事件要改 5 个地方；轮询 1 行。
3. **零分配、零热路径开销**：`rt.state` 是 `readonly` 公开字段（`oathkeeper-runtime.ts:47`），直接读就是一次属性访问。

**代价**：拿不到"这一帧刚变相位"的边沿。解法 = view 内部存 `lastPhase`，只在变化时做一次性副作用（重置 walk/attack 计时）。**注意**：`biteDealt` 是唯一"事件性"输入，且它**已经**由 `update()` 返回——不必另设总线。

### 3.4 depth 与脚底线（具体数字）

**depth 现状（实测全仓）**：`telegraph 5` / `marker 20` / `chest 25` / `aura 40` / `bounds 50` / `shockwave 85` / `orbit 90` / **`player 100`**（`player.ts:52`）/ **敌人 0**（`src/enemies/` 下**零** `setDepth`，即 Phaser 默认 0）/ 地图 `-100…-90`。

**建议 `OATHKEEPER_DEPTH = 30`**（主选）
- 高于敌人(0) → 不会被 56px 的敌群淹没（**这才是本次修复的意义**：他必须始终看得见）
- 低于 aura(40) / orbit(90) / player(100) → 状态图标与玩家永不被压
- **代价**：他的剪影会盖住 `marker-*` 地面标记(20)与宝箱(25)。可接受（他常规距玩家 60px，宝箱瞬拾）
- **备选 `-1`（严格背景层）**：被敌人完全遮挡，视觉更"背景护卫"，但与"让他看得见"的初衷相抵；改一行即可切换，**建议做成常量便于实机对比**

比玩家低多少：**70**（100 − 30）。数值本身无耦合，只影响叠放。

**脚底线（交付单漏项，改错会明显穿帮）**
- 玩家：128 画布、`footY=127`、`origin 0.5` → 脚在锚点**下方** `127.5 − 64 = 63.5` 世界 px
- 守誓者（新 192 帧）：`footY=191`、`origin 0.5` → 脚在锚点下方 `191.5 − 96 = 95.5` 世界 px
- ⇒ **`sprite.y = state.y − 32`**（96 − 191.5 + 127.5 = 32.0，整数 32）
- 若照字面写 `sprite.y = state.y`，他的脚会**沉到地面下 32px**——占他体高的 19%，肉眼立刻能看出"站在坑里"
- **不选 `setOrigin(0.5, 0.9974)` 的原因**：全仓角色/敌人一致用默认 origin（`player.ts` 也是），集中在一处用常量偏移比"给一个精灵改 origin"更不容易被后人误读成特例

**scale**：`applyCombatDisplayScale(sprite)` 会在**每次换帧后**自动给出 192→1、48(墓碑)→2.667 —— 直接复用（`combat-display-scale.ts:14`）。**不要**自己写 `setScale(1)`，否则切墓碑时会忘了改回来。
