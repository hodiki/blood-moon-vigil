## 0. 一句话结论

1. **选定方案**：把 `webServer.command` 从 `npm run preview -- ...` 改为**直连 Vite CLI**（`node <viteBin> preview --port 4173 --strictPort`），将 Windows 下 webServer 的进程树从 **4 层压到 2 层**（`cmd → node(vite)`），收窄 `taskkill /T` 的漏杀面。**断言 / 退出码语义零变化。**
2. **关键核实结论**：任务书候选方案 ①「`gracefulShutdown`」—— 该配置项在 Playwright 1.62.1 **受支持，但在 Windows 上被忽略**（源码在 win32 分支直接抛错并回退 taskkill；官方文档亦明示 *ignored on Windows*）。**故它不是本机修复手段，予以排除。**
3. ⚠ **知识诚实声明（重要）**：**本机在修复前连续 35 次 `npm run test:e2e` 均未能复现该 hang（0/35）**；隔离探针对 `taskkill /T` 回收率实测亦为 100%（原命令 6/6 回收干净）。修复后 8/8 次干净退出、`exit 0`。故本报告的"修复"定位为：**针对已确认失败机制的防御性加固（缩短派生链）+ 完整根因与规避方案登记**，而**非**"复现 → 修复 → 回归"闭环。若用户所在环境仍复现，请直接采用 §6 的规避方案。

## 1. 问题与根因（代码级）

### 1.1 症状（沿用 E 批观测）
- 断言全过、`1 passed` 已打印，但 `playwright test` **进程不自行退出**；被外部终止后残留 `vite preview`（:4173）。
- E 批原文（`当前版本收口-工程批E执行报告-2026-10-09.md:140`）：
  ```
  ok 1 tests\smoke\smoke.e2e.spec.ts:18:1 › 游戏启动冒烟… (6.6s)
  1 passed (2.4m)
  ```
  用例本体 6.6s，整轮却 **2.4m** ⇒ 约 2.3 分钟耗在**收尾阶段**。

### 1.2 Playwright 关停 webServer 的确切路径（1.62.1 源码）
| 步骤 | 位置 | 行为 |
|---|---|---|
| 启动 | `playwright/lib/runner/index.js:856-865` | `launchProcess({ shell: true, detached: false（win32） })` → 直接子进程 = `cmd.exe` |
| 管道 | `playwright-core/lib/coreBundle.js:8899` | stdio = `["pipe","pipe","pipe"]`（webServer 的 stdout/stderr 是 `pipe`，由 Playwright 主进程持有读端） |
| 关停入口 | `index.js:836-839` | `teardown()` → `await this._killProcess()` |
| 优雅关闭 | `index.js:866-880` | `attemptToGracefullyClose()` —— **win32 分支直接 `throw new Error("Graceful shutdown is not supported on Windows")`**（:867-868） |
| 回退强杀 | `coreBundle.js:8979-8999` | `killProcess()` → **`taskkill /pid <直接子进程 PID> /T /F`**（:8987-8988），`/T` 依赖父子链回收**整棵进程树** |
| 完成判定 | `coreBundle.js:8947` | `spawnedProcess.once("close")` → `waitForCleanup` resolve |

### 1.3 失败机制（为何"断言过了却不退出"）
原命令 `npm run preview -- --port 4173 --strictPort` 在 Windows 下的进程树：

```
cmd.exe            ← Playwright 直接子进程（taskkill /T 的锚点）
└─ node (npm)      ← 中间层
   └─ cmd.exe      ← npm 跑脚本的 shell
      └─ node (vite preview)   ← 真正的服务器，继承 Playwright 的 stdout 管道
```

- `taskkill /T` 按父子链遍历；**任一中间层先退出 / 被孤儿化，遍历即漏掉 vite 孙进程**。
- 存活的 vite 孙进程**继续持有 Playwright 为 webServer 创建的 stdout 管道**（§1.2 第 2 行）⇒ `close` 事件**永不触发** ⇒ `waitForCleanup` 不 resolve、且 pipe 读端持续持有事件循环 ⇒ **Node 进程挂起**（用例结果早已打印）。用外部 `kill` 强杀 npm 时，孙进程被孤儿化而残留 —— 与"实测残留 vite"一致。

> 结论：**派生链越短，`taskkill /T` 越不易漏杀**。修复即围绕这一点。

## 2. 方案评估（候选 1–4）

| # | 方案 | 结论 | 理由 |
|---|---|---|---|
| ① | `webServer.gracefulShutdown` | **排除** | 1.62.1 支持该字段，但 **win32 上被忽略**：源码 `index.js:867` 直接 throw 并回退 taskkill；官方文档明示 *"Windows doesn't support SIGTERM/SIGINT … ignored on Windows"*。在目标 OS 上为 **no-op**，不能修复本问题。 |
| ② | `globalTeardown` 显式回收（tree-kill） | **备选，未采用** | 需按端口/命令行匹配 PID。与 `reuseExistingServer: !CI` **语义冲突**：本地复用"开发者已起的 dev server"时会被误杀（Playwright 复用时不持有其 PID，无法区分"我起的"与"复用的"）。且若挂起发生在 `teardown` 的 `await waitForCleanup` 阻塞时，`globalTeardown` 可能根本轮不到执行。风险 > 收益。 |
| ③ | **webServer 配置调整（消灭派生链）** | **✅ 采用** | 直连 Vite CLI 把树压到 `cmd → node(vite)`（2 层），从**结构上**收窄漏杀面；**零断言/退出码影响**；跨平台一致、无新依赖。 |
| ④ | 其它：wrapper 解耦 stdio / 自管进程组 / 改由外层脚本兜底 | **评估后放弃** | 需新增 wrapper + PID 文件 + teardown 接线（属"大幅改造"），超出 P2 与本任务"不大幅改造"边界；作为 §6 兜底方案登记。 |

**为何 ③ 优于 ①/②**：① 在目标 OS 无效；② 有误杀复用服务器的真实风险；③ 是唯一直击根因（漏杀面）、且**无副作用**的最小改动。

## 3. Playwright 版本与所用配置项支持性核实

- **版本**：`npx playwright --version` = `Version 1.62.1`；`node_modules/@playwright/test/package.json` 与 `node_modules/playwright-core/package.json` 均为 `1.62.1`。
- **`gracefulShutdown` 支持性结论：字段存在，但 Windows 不生效。**
  - 类型定义存在：`node_modules/playwright/types/test.d.ts:10776`（`gracefulShutdown?: { signal: "SIGINT"|"SIGTERM"; timeout: number }`）。
  - 运行时在 win32 直接短路：`node_modules/playwright/lib/runner/index.js:866-868`
    ```js
    attemptToGracefullyClose: async () => {
      if (process.platform === "win32")
        throw new Error("Graceful shutdown is not supported on Windows");
      if (!this._options.gracefulShutdown) throw new Error("skip graceful shutdown");
      ...
    }
    ```
  - 官方文档原文：*"Windows doesn't support SIGTERM and SIGINT signals, so this option is ignored on Windows."*
  - ⇒ **明确结论：不支持在 Windows 生效，不能作为本机修复手段。**（E 批建议的 `gracefulShutdown:{ signal:'SIGKILL' }` 还另有两处问题：`SIGKILL` 不在合法联合类型 `SIGINT|SIGTERM` 内，且同样被 Windows 忽略。）
- **本方案所用配置项**：`webServer.command`（string，标准字段）—— 无版本兼容风险；仅改了命令内容与派生链形态。

## 6. 若用户环境仍复现 · 规避方案（登记，未硬凑）

1. **首选：e2e 门禁跑 Linux runner。** Linux 下 Playwright 走 `process.kill(-pid, SIGKILL)`（以**进程组**为单位，`detached:true`），不受 Windows `taskkill /T` 的父子链局限；本次新增的 `gracefulShutdown` 在 POSIX 亦生效。
2. **兜底（坚持 Windows）**：新增 `tests/smoke/serve-preview.mjs`（自持 vite 子进程并写 PID 文件）+ `globalTeardown`（按记录的 PID 精确 `taskkill /T /F`）。**注意**必须按"我起的那棵树的 PID"回收以不误伤 `reuseExistingServer` 复用的服务器 —— 为此需引入 wrapper，属较大改造，本次未做。
3. **最外层兜底**：门禁脚本用 `npm run build && start /wait npx playwright test`，外层再对 :4173 兜底 kill（粗糙但有效）。
