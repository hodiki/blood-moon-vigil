## 〇、一页结论（给排期）

**总判定：架构可继续承载内容，不能按八份 GDD 做局内验收。**

配置表与纯函数引擎大体对齐 0.8；缺口几乎全在 **PlayScene 最后一公里**。单测绿锁的是表形状与公式，不是「Boss 会不会放血池 / 眩晕敌会不会撞人」。这解释了初步手测「需求没做完」。

| 维度 | 结论 |
|---|---|
| 局内可玩完成度（相对 GDD） | 约 **四成**。升级池 v3 抽取已切生产；专武 2 选 1 正常局可用；圣物 / Boss 技能体 / 突袭前扑 / CC 进伤害链基本未进对局 |
| 架构 | 四支柱仍在（按域 `balance/`、武器注册表、帧名契约、缺帧回退）。集成债恶化：`PlayScene.ts` **1665 行**（v0.5 审查为 1277，+30%） |
| 与 NV-INTEG-FIX 的关系 | 那批修的是树点不了、2 选 1 流程、灯环可见性等**表面问题**。本文件是更深的 GDD 行为层，不重复开那些已修单 |
| 不要先做 | 不要再加配置表「对齐 GDD」；不要在 A–E 接线完成前把 XP c 案 / `budgetPiecewise` 写进运行时 |

**修复总顺序（强制）：A 战斗正确性 → B 专武最后一公里 → C 怪物身份 → D 成长接线 → E 共鸣补完 → F 拆场景/清双轨 → G 难度切换（等模拟冻结）。**

工作量档沿用仓内口径：S ≤1 人日 / M 2~5 / L >5。下列人日为工程纯实施（不含美术、数值复测轮）。

## 一、阅读与实施纪律

1. **设计权威**：`design/official-v1/` 八份 GDD。旧 `design/gdd/`、`gdd-weapons-v2`、`gdd-active-skill`、`gdd-upgrade-pool-v2` 只作追溯，禁止当实施规格。
2. **先接线、后加表**：本轮缺口的默认形态是「表已有、函数已有、场景未调」。修之前先 grep 配置 id / 引擎函数是否已被 `PlayScene` 调用。
3. **生产路径只有一条**：升级抽取 = `rollThreeV3` + `applyUpgradeByIdV3`。禁止重新启用 `rollThree` / `rollThreeV2` / `WeaponSystem.evolve()`。
4. **测试分层**：配置断言不够。每条 P0 必须带 **运行时或场景级** 用例（至少：纯函数 + PlayScene 协作测或 `?qa=1` 手测清单）。`PlayScene` 当前 **0** 个场景级单测。
5. **`?smoke=1` / `?bench=1` 不是玩家路径**：这两条目前跳过 `applyLoadout`，专武恒 disabled。修 B 批时必须让 smoke/bench 走默认 loadout，否则 QA 会误判专武未做。
6. **批次边界**：A–E 可以并行到不同人，但 **A 必须先于 C 的 Boss/精英 CC 验收**（否则眩晕/易伤测不准）。G 不得提前插入。

## 三、架构结论（给后续改造约束）

### 3.1 数据流（现状）

```
session-selection + save
        ↓
config/balance/*     →  纯逻辑（spawner / upgrade-pool-v3 / status-engine / relic-engine / …）
        ↓
PlayScene.create()   →  池 / WeaponSystem / Spawner / 树 / 衍生技 / 质变管线 / DOM
        ↓
update() RUNNING     →  玩家 → 生成 → 敌 AI → 精英/Boss 桩 → 武器 → XP
        ↓
GameEvents           →  DOM UI（只读 + emit）
```

文档（`docs/architecture/architecture.md`）仍写「四态机、12 项池、场景只转发」。现实是 **六相位**（含 `PROLOGUE` / `EXCLUSIVE_SELECT`），且 PlayScene 持有 Boss 技能消费、天赋运行时、质变管线、衍生技施放、守誓者、bench/smoke。

### 3.2 结构性约束（修 bug 时不要再恶化）

| 约束 | 说明 |
|---|---|
| 新系统禁止继续把完整行为写进 `PlayScene` | 场景只调 `xxxDirector.update()` / `onEvent`；判定体、AI、掉落放回 `enemies/` `relics/` `combat/` |
| 伤害与 CC 只走状态层 | 禁止再给敌人加 `stunnedUntil` / `markUntil` 平行字段的新消费者 |
| 专武装配只走 `applyLoadout` | smoke/bench/默认角色对，全部调用同一函数 |
| 死路径隔离优于删除叙事资产 | `evo_*` 图鉴可留「退役区」；`WeaponSystem.evolve()` 调用面必须保持为零 |

### 3.3 文档债（F 批顺手，不阻塞 A–E）

- 更新 `docs/architecture/architecture.md`：六相位、v3 池、专武/树。
- `PlayScene.ts` 文件头仍写「四态状态机」——改注释。
- `package.json` 版本与 0.8 里程碑对齐（由主理人定 tag，工程不要私自改 semver 政策）。

## 四、P0 验收阻断（必须进本轮修复）

每条格式：**现象 → 根因 → 改法 → 验收 → 建议档**。

### P0-1 圣物整层不在局里

- **GDD**：`gdd-exclusive-weapons.md` §3.4 / 尾章。Boss 必掉 1 + 祭坛概率第 2；专用键；CD 240s；每局 1~2 次；伤害 <5%。
- **现象**：整局无圣物掉落、无按键、无 HUD。
- **根因**：`src/relics/relic-engine.ts` 的 `grantRelic` / `useRelic` 仅被单测调用。`PlayScene.onBossDefeated` 无掉落。无祭坛实体。键盘 `skill1`/`skill2` 目前都绑衍生技（`keyboard-input.ts`），没有第三/第二技能语义给圣物。
- **改法**：
  1. PlayScene 持有 `RelicRuntimeState`；Boss 击败按本图池 `grantRelic`（保底 1）。
  2. 祭坛可本批做 **地图事件占位**（一种可交互点 + 概率第 2 枚）；若本迭代砍祭坛，必须在本条验收写明「仅 Boss 1 枚」，并回写 GDD 挂账，禁止静默砍。
  3. 输入：衍生技保留 Space；圣物用独立键（建议 Q / 手柄 LB，移动端第二技能钮）。`control-manifest` 同步。
  4. HUD：CD 环 + 剩余次数 1~2（GDD §7）。演出可先 1.5s 全屏色板，允许设置降级。
  5. `relic_silver_tide` 引擎内仍是 no-op，本批必须按 GDD 尾章补效果，禁止只接线空技能。
- **验收**：墓地 Boss 击杀必得 1 枚；键可释放；第二次受 CD 240s 限制；关技能仍可打 Boss（R2-14 不因圣物阻塞）。
- **档**：M（接线 + HUD + 1 个祭坛占位）；效果补全若跟尾章逐条对齐再 +S~M。

### P0-2 眩晕冻移动，不挡接触伤害

- **GDD**：`gdd-status-effects.md` 硬控期间目标不造成接触伤害。
- **现象**：眩晕敌站桩仍能把玩家撞死。
- **根因**：`src/combat/contact.ts` 已支持 `statusStunned?: (now) => boolean`，`PlayScene` 碰撞回调（约 L548）只传了 `hurt`，未传 `statusStunned`。移动侧已读 `cc.stun`。
- **改法**：碰撞处传入 `statusStunned: (now) => queryStun(enemy.cc, now)`（或引擎等价查询）。补单测：眩晕窗口内 `playerEnemyContact` 不扣血。随后从接触路径删除对 `stunnedUntil` 的依赖。
- **验收**：提灯/审判等施加眩晕后，贴脸 1s 玩家 HP 不变（无敌帧外）。
- **档**：S。

### P0-3 易伤未进入通用伤害链

- **GDD**：易伤对**所有伤害** ×(1+值)。
- **现象**：通武/大部分衍生技打不到易伤；只有专武 `exclusive-math.ts` 调 `damageTakenMultiplier`。
- **根因**：`weaponDamageOnTarget`（`active-skill-effects.ts`）仍读 legacy `markUntil`。`computeHitDamage` / `hitEnemy`（`damage.ts`）无状态层。
- **改法**：
  1. 在 `damage.ts`（或唯一命中入口）乘 `damageTakenMultiplier(cc, now)`。
  2. 投射 / 环绕 / 召唤 / 冲击波 / 衍生技全部改走该入口；禁止各武器自己乘一遍。
  3. 迁移完成后删除 `markUntil` / `markDamageMult` 的新写入；旧字段仅允许读兼容一层然后去掉。
- **验收**：同一易伤目标，专武与 `wpn_a_1` 飞弹增伤比例一致（单测矩阵）。Boss 免疫易伤（GDD 抗性表）。
- **档**：M。

### P0-4 突袭型三敌无前扑

- **GDD**：`gdd-enemies-v3.md` 血犬 / 血蝠 / 暗影狼 = 突袭：100px 起手、0.25s 前摇、90px@300px/s、CD 2.5s。
- **现象**：三敌只是高速直线追击（`unlockAt` + `speed`）。
- **根因**：`enemy-ai-runtime.ts` 只驱动 `aura` / `summon` / `charge`。`ENEMY_BEHAVIORS` 无 lunge 模板；`g1_2` / `g2_2` / `g3_2` 未挂行为。
- **改法**：新增 `kind: 'lunge'`（可复用 charge 的 windup→dash 骨架，参数按 GDD）。三 id 登记同一模板、地图微调只改 `unlockAt`。预警用现有 `TelegraphLayer`。
- **验收**：`?qa=1` 下进入 100px 可见前摇；落空有 CD；与冲锋猎手（g3_4）手感可区分。
- **档**：M。

### P0-5 精英技能化未按 180s 门控（轨③）

- **GDD**：`gdd-spawner-v2.md` / 难度 §5.4 轨③：180s 前精英 = 厚血无技能；180s 起技能化 + 词缀。
- **现象**：S2 保底精英（120s）已满技能。
- **根因**：词缀 `unlockAt: 180` 已接。`PlayScene.stepEliteSkills` 对池内所有 `tier==='elite'` 步进，无局时门。守墓者/畸体/石甲狼配置上随时可进池。
- **改法**：`EliteSkillDirector.update` 增加 `runTimeSeconds`；`< 180` 只走厚血接触，不进 windup。180s 前已在场的精英：到点后**下一循环**才开技能（不要半招切形态）。掷骨者/忏悔者 `unlockAt: 180` 保持生成门，与技能门一致。
- **验收**：120s 守墓者无扫击预警；181s 新精英有技能。单测锁门控。
- **档**：S~M。

### P0-6 Boss 五槽几乎是距离伤害桩

- **GDD**：`gdd-enemies-v3.md` 四 Boss × 五技能槽（扇形/环形、血池/雾/井、冲锋/嚎叫/扑击、分身/引力/月相/月坠）。
- **现象**：调度器在转 CD，结算是 `dist <= 160` / `<= 300` 扣血；无地面区、无冲锋线、无月坠区。幻影用 `enemy_g1_1` 占位。
- **根因**：`boss-skill-engine` 发事件；`PlayScene.stepBossSkillRuntime` 用距离桩消费。注释写明「telegraph 演出 W-13 内容批补」。
- **改法**（本轮最低可验收，禁止再加桩）：
  1. 把技能消费从 PlayScene 抽到 `boss-skill-runtime.ts`（或扩引擎），场景只提供 spawn/hurt/fx 端口。
  2. 每 Boss 至少 **2 个可解技能**落地（判定形状 + 预警 + 走位能躲），其余可保留简化但必须不是全图 dist 桩。
  3. 建议优先：boss_1 扇形 180°、boss_2 血池圈、boss_3 冲锋直线、boss_4 月坠落点圈。
  4. 幻影不要用行尸面板；HP1 + noXp + 接触伤按表。
- **验收**：手测每 Boss 能靠走位躲过至少 1 个技能；清召唤时间不主导战斗（MD-4 方向，本批先行为正确）。
- **档**：L（可按 Boss 拆 4 个 S~M PR）。

### P0-7 专武 / 衍生若干关键行为未消费

下列均已有配置或事件，运行时丢弃。**本条拆子项，禁止只修一个当整条关单。**

| 子项 | GDD | 现状 | 改法 |
|---|---|---|---|
| P0-7a 守誓者质变 `mc_bell_2` | 转移 65%、啃咬 14、墓碑 4 HP/s、复活 70% | `oathkeeper.applyCompanionMachine()` 从不调用；`upgrade-apply-v3` 只写专武 behavior | 卡 2 写回时对 `OathkeeperRuntime` 调 `applyCompanionMachine` |
| P0-7b 安魂曲协同 | 守誓者回满 / 墓碑进度充满 | `tryCastActiveSkill` 不传 companion 回调 | `castRequiem` 注入 `healFull` / `fillReviveProgress` |
| P0-7c 圣铃治疗 | 每 8s 治自身 **与** 守誓者 8 HP | `stepBell` 只 `player.stats.heal` | healSink 同时写 companion HP |
| P0-7d `dv_blood_rage` | 6s 挥击不耗 HP | 只上玩家 `RageBuff`；`stepAxe` 仍 `spendHp` | 狂化窗口 `selfHpCost=0` 或 axe 读 rage 旗 |

- **验收**：修女选圣铃 + 卡 2 后转移比例变化；安魂曲满血守誓者；巨斧+狂化期间 HP 不因挥击下降；提灯闪后射速可感知加快。
- **档**：M。

### P0-8 P4「已取」查错 id

- **GDD**：P4 窗口第 8~14 次升级；错过本局不再出现。
- **现象**：`buildUpgradeContext`：

  ```ts
  derivativeUpgradeTaken: this.upgradeState.stackOf(EXCLUSIVE_TO_DERIVATIVE[this.currentExclusiveId]) >= 1
  ```

  `EXCLUSIVE_TO_DERIVATIVE` 的值是 `dv_revolver_burst` 等**技能 id**；栈里是 `up_d_revolver` 等**升级 id**。taken 恒 false。
- **根因**：id 空间混用。`maxStack=1` 能阻止「取过再保底」，但 **错过窗口后卡仍可随机进三选一**，违反「不再出现」。
- **改法**：
  1. `stackOf(DERIVATIVE_UPGRADE_MAP[derivativeId])`。
  2. `buildV3Candidates` 对 `up_d_*` 增加：窗口外且未取 → 直接不进池（不只靠 P4 席位）。
- **验收**：单测「取过 → 池无该卡」；「upgradeCount>14 且未取 → 池无该卡」；PlayScene 上下文用 `up_d_*`。
- **档**：S。
