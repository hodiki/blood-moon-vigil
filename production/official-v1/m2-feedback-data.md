## 三、①a 武器类解锁卡出现分布 —— 为什么玩家体感「只遇召唤（D）」？

| 指标 | 模型 A | 模型 B | 模型 C |
|---|---|---|---|
| B 类解锁卡 offer 占比 | 7.25% | 5.10% | 6.42% |
| C 类解锁卡 offer 占比 | 7.13% | 5.11% | 6.44% |
| D 类解锁卡 offer 占比 | 7.11% | 5.12% | 6.38% |
| **解锁卡中 B/C/D 之比** | **33.76 / 33.16 / 33.08** | 33.28 / 33.34 / 33.38 | 33.38 / 33.48 / 33.14 |
| 首把新武器解锁类分布 | B 32.4 / C 33.7 / D 33.9 | B 33.9 / C 34.1 / D 32.0 | B 33.4 / C 34.2 / D 32.5 |
| 有解锁的局占比 | 85.6% | 99.7% | 95.1% |
| 每局平均解锁武器数 | 1.275 | 2.305 | 1.759 |

**判断（数据 × 结论）**：
1. **B/C/D 三类的解锁卡出现与点选在全部模型下 ≈1/3 均等** —— 代码与数据都证明没有 D 类偏置，机制无 bug。
2. 玩家「只遇到 D」最可能的来源：**解锁任一非 A 类后，该类强化项权重 ×2**（GDD §3.6.2 引导成型）。一旦首把解锁了 D，D1/D2/D3 召唤强化卡会持续高频出现（权重翻倍），观感上「满屏召唤卡」；而 B/C 的解锁卡仍以 ×1 潜伏在池里。这是**同类惯性放大**，不是抽取偏置。
3. 另一个来源：单局 5~7 次升级只解锁 ~1.3~2.3 把武器，样本极小；真机 3 局全遇到 D 类解锁的概率 ≈（1/3）³≈3.7%～，不罕见。
4. **附带发现**：解锁武器在 9 把非初始武器间接近均匀（wpn_c_1=741 最高 / wpn_b_1=677 最低，模型 A），无单武器热点。

## 四、①b 进化卡达成率 —— 「持钥从未出紫色进化卡」成立且原因明确

| 指标 | 模型 A | 模型 B | 模型 C |
|---|---|---|---|
| 看到进化卡（★★ 入三选一）的局 | 3/5000 = **0.06%** | 12/5000 = **0.24%** | 89/5000 = **1.78%** |
| 完成进化的局 | 2/5000 = 0.04% | 12/5000 = 0.24% | 89/5000 = 1.78% |
| 平均每多少局见到 1 次进化卡 | ~1667 局 | ~417 局 | ~56 局 |
| 条件满足局（类≥3+对应钥） | 11 (0.22%) | 27 (0.54%) | 289 (5.78%) |
| 条件首次满足的平均升级序号 | 6.18 | 6.19 | 5.99 |
| 条件满足后「进化卡实际出现在三选一」 | 3/11 = 27.3% | 12/27 = 44.4% | 89/289 = 30.8% |

**瓶颈拆解（未达成进化的局，互斥可叠加）**：

| 瓶颈 | 模型 B | 模型 C |
|---|---|---|
| 某已拥有可进化武器类累计强化 <3 | 81.66% | 52.64% |
| 未持「对应」钥（持了别的钥/没持钥） | 82.52% | 63.84% |
| 类钥都够，但剩余升级里进化卡没被抽进 3 张 | 2.04% | 11.94% |

**进化达成率 × 单局升级次数敏感度（各 5000 局）**：

| 单局升级次数 | 5 | 7 | 10 | 14 | 18 |
|---|---|---|---|---|---|
| 模型 B 完成进化 | 0.00% | 0.24% | 1.66% | 7.42% | 20.48% |
| 模型 C 完成进化 | 0.54% | 4.12% | 17.16% | 37.06% | 59.20% |

**判断（数据 × 结论）**：
1. **进化卡入池逻辑正确**（条件满足即入池权重 ×3，见 §一），但 **5~7 次升级的局内几乎不可能达成**：需把 ~4~5 次升级投给「同一类 ≥3 + 对应钥」（占 5~7 次的绝大部分），而三选一池 31 项稀释后极少能凑齐；且**凑齐时往往已到第 6 次升级**，剩余次数内进化卡还要再被抽进 3 张（只有 ~27~44% 机会）。
2. 「持钥却没出紫卡」的最常见实情是**钥不对应**：例如守夜人持有 key_silver（对应圣银火铳 wpn_a_3）但只拥有血月猎手 wpn_a_1（需 key_scope），条件永远不满足 —— 模型 B 中 82.5% 的局卡在「未持对应钥」。
3. **敏感度是决定性证据**：若真机单局升级次数 >10，进化会明显可达（模型 B 10 次 → 1.66%，14 次 → 7.42%）。这直接牵出一个 **GDD 内部口径矛盾**（见下框），需设计裁定。

> ⚠️ **GDD 口径矛盾（工程视角标记，需设计裁决）**：
> - `gdd-upgrade-pool-v2.md` §5.2 与任务标准模型采用「**单局 5~7 次升级**」；
> - 但同 GDD §3.0 / §5.1 与 `balance.ts` XP 曲线 `need(n)=5+3(n-1)` + 6 分钟累计经验 ~1100~1200 → **Lv~27 ≈ 26 次升级 offer**（每次升级都触发三选一，`xp-manager.ts:176-181` + `PlayScene` 已核实）。
> - 两者相差 ~4~5 倍，直接决定进化卡「几乎不可能」还是「常客」。**若真机 7 分钟实际 ~20+ 次升级，则「从未见进化卡」不能用稀有度解释，需另行核查玩家实际升级次数/池组成；若实际仅 5~7 次，则本报告 §四 的稀有度结论成立。** 建议设计先定「单局 offer 次数口径」，再定进化数值。

## 五、①c 三选一质量（对应反馈②）

| 指标 | 模型 A | 模型 B | 模型 C |
|---|---|---|---|
| 至少 1 张机制型/行为改变卡 | **99.79%** | 99.74% | 99.73% |
| 3 张全是纯数值卡 | 0.21% | 0.26% | 0.27% |
| 3 张全是「全局数值项」(up_g_1~4) | 0.05% | 0.04% | 0.05% |
| 至少 1 张新武器解锁/进化卡 | 51.80% | 38.41% | 47.11% |
| **0 张强化当前 build 卡（全泛用/方向改变）** | **29.01%** | 21.61% | 27.05% |
| 强化当前 build 卡（已拥有类强化+主动技+进化）offer 占比 | 33.66% | 40.87% | 35.77% |

**分类 offer 占比（模型 A 无偏基线）**：evolution 0.00% · unlock 21.49% · class 25.53% · key 18.90% · active 8.12% · global 25.96%。

**判断（数据 × 结论）**：
1. 「选项里没有机制卡」**不成立**——99.7%+ 的三选一至少 1 张机制/行为卡，机制型 85% 的池口径在 offer 层面兑现。
2. 「全是数值卡」**不成立**——仅 0.2~0.3% 的三选一 3 张全数值。
3. **「与 build 意向无关」成立且有数据支撑**：强化当前 build 的卡仅占 offer 的 ~34~41%（约 2/3 的卡是全局泛用 / 钥 / 未拥有类解锁卡）；**21.6%~29% 的三选一里没有任何一张强化当前 build 的卡**。玩家对「无关」的体感来自这里，而非「数值卡数量」。
4. 解锁卡（21.5%）既是亮点也是「方向漂移」来源：它是新内容（正反馈），但随机解锁会把 build 拉向随机方向，计划感弱。

|---|---|---|---|
| 前 3 次升级内出现「新武器/进化卡」 | 94.86% | 95.04% | 95.04% |

**判断（数据 × 结论）**：前期（前 3~4 次升级）几乎必见新武器/机制卡（≥95%），机制卡必现（100%）。**前期「内容供给密度」充足**，玩家「选项无聊」不是缺新内容，而是 §五 的「build 定向性弱 + 泛用数值卡价值感低」问题。

## 七、② 纯数值卡占比 / 可重复数值项（反馈②数据支撑）

| 指标 | 模型 A | 模型 B | 模型 C |
|---|---|---|---|
| 纯数值卡（up_g_1~4 + key_tome/key_silver）offer 占比 | 17.08% | 16.45% | 17.08% |
| 全局数值项（up_g_1~4）offer 占比 | 11.66% | 11.11% | 11.50% |
| up_g_1（伤害+15%，可重复）被 offer 的三选一占比 | 8.79% | 8.15% | 8.54% |
| up_g_1 被点选（run 级） | 16.70%（0.179 次/局） | 0.84% | 0.92% |

**判断（数据 × 结论）**：
1. **纯数值卡不是 offer 主力（16~17%）**，「数值选项太多」的体感更多来自「数值卡出现时机差/价值感低」（+15% 伤害 vs 新武器）而非频率。
2. **up_g_1 是唯一无限可重复项**：随机玩家（模型 A）每局点选 0.18 次、16.7% 的局至少点 1 次；意向玩家几乎不点（<1%）。它是「满级回退兜底」，正常局不会成为主力，但**后期池越空它出现率越高**，是「无聊感」的尾部来源（本模型 5~7 次升级内不显著）。

## 九、给设计的裁定建议（工程视角，仅供裁定）

1. **先裁定「单局 offer 次数口径」**（5~7 vs Lv~27≈26）。这是进化卡可达性的总开关（§四敏感度表）；不同口径下结论相反，务必先定。
2. 若维持 5~7 次升级：**进化卡在当前池稀释下事实上不可达**（≤1.78%），建议设计侧考虑：类强化权重再上调 / 钥按「已持同类钥时对应钥权重上调」/ 提高进化卡权重（×3→×5）/ 或接受「进化=超长线目标」并改宣发预期。
3. 「与 build 意向无关」的实感来自**泛用卡（全局+钥）≈46%**：可考虑把部分 key 改成「机制联动」（如 key_scope 同时是 A 类强化入口）或三选一内做「至少 1 张与已持有武器/当前 build 相关」的软保证（类似 Demo 首级强制武器，但作用于每轮）。
4. 纯数值卡本身不超量，**价值感知**问题是主因：可考虑数值卡带「可选升级型」文案或与武器联动的数值（而非全局通用），降低「+15% 通用伤害」的鸡肋感。
5. 「只遇 D」为感知问题，无需改抽取；如要降低类惯性观感，可在解锁卡卡面标注「解锁后该类强化权重提升」提示，或把解锁后 ×2 引导改为 ×1.5。

## 十、复现与限制

- 模拟脚本：`.tmp-analysis/sim-m2-feedback.ts`（主模拟 + 敏感度）· `.tmp-analysis/debug-evo.ts`（进化条件复核）· 输出 `.tmp-analysis/sim-output.txt`。**均为临时文件，可整体删除**（不提交、不入 tests/）。
- 运行方式：`node_modules/.bin/vite-node .tmp-analysis/sim-m2-feedback.ts`（复用 src/ 真实模块）。
- 限制：① 选卡模型是对玩家行为的近似（A/B/C 三档覆盖无偏/意向/上限，结论中对模型不敏感处已注明）；② 未建模玩家死亡提前结束/捡不满经验等（5~7 次升级为既定标准模型）；③ 「强化当前 build」口径 = 已拥有类强化 + 当前角色主动技 + 进化卡，未含「解锁新武器」（解锁算方向改变）。
