## 2. 口径 B 最终实现语义（一段话 + 流程）

**语义**：血月化身（`boss_4`）是**独立事件 / 特殊 Boss**（4:30 后稀有随机遭遇），**不是 6:00 进度门**——其击杀**不发 `BossDefeated`**、不触发胜利终局、不记通关存档、不按 `victory=true` 计功绩；其产出 = 图鉴隐藏条目 `codex_boss_boss_4` + 事件条目 `codex_event_6` + 稀有宝箱 + 功绩 `+5`（`avatarKills`）+ 圣物保底。圣物保底渠道 =「**血月化身优先 + 地图 Boss 兜底**」，两渠道**共用同一 `hasGuaranteedDrop` 闸门**（先到先得，第二次 no-op），保住红线「每局保底 1 枚」。

**流程**：

```
化身出场 (spawnAvatar) ──► grantBossGuaranteed() 发保底第 1 枚（化身 = 更早的更优渠道）
      │
化身被击杀 ──► Enemy.kill() 发 EnemyKilled { enemyType:'boss', enemyId:null, bossId:'boss_4', ... }
      │
      ├─(订阅序①) killLoot.onEnemyKilled ──► contentId='boss_4' ──► recordKill('boss_4')
      │        └► 图鉴隐藏条目 + codex_event_6 + avatarKills+=1（功绩 +5）+ dropRareChest
      │
      └─(订阅序②) PlayScene.onAvatarKilled ──► ① bossConsumer.endFight()（清化身技能召唤物/复位技能区）
                                              ② spawner.boss4OnField = false（方阵恢复掷点）
                                              ③ 不 finishGame / 不 recordMapCleared / 不 victory 计功绩

6:00 (onBossTime) ──► clearAll() + spawnBoss()
      └► grantBossGuaranteed() —— 化身已发则 no-op（兜底）；地图 Boss 击杀 ──► BossDefeated
              └► onBossDefeated(bossId 守卫) ──► 唯一 finishGame(true) 入口
```

## 4. 化身产出链重构结论（含 `recordKill` vs `recordTrigger` 查证裁决）

### 4.1 死代码根因
旧 `onEnemyKilled` 的图鉴块判据为 `if (payload.enemyId)`。Boss 实体 `spawnByBossConfig` 恒置 `enemyId = null`（有意语义），故**对 Boss/化身恒 false** → 整块产出链（图鉴首杀、首杀功绩、化身分支）对 Boss **死代码**。

### 4.2 重构
入口判据改为 `contentId = payload.bossId ?? payload.enemyId ?? null`：
- Boss/化身：`contentId = bossId`（`boss_1/2/3/4`）
- 15 内容敌：`contentId = enemyId`
- 旧 kind 三敌：两者皆 null → 跳过（语义不变）

分母/面板链同步改用 `contentId`（Boss 现计入 `recordTotalDamage` 分母——修复了此前 Boss 分母缺失）。

### 4.3 `recordKill` vs `recordTrigger` 查证裁决
- `codex.ts:99` 中 `boss_4` 条目 = `unlock: 'kill'`，`MOON_AVATAR_ENTRY_ID = 'codex_boss_boss_4'`（`codex.ts:212`）。
- `CodexTracker.recordKill('boss_4')`：`boss_*` 前缀 → 记 `codex_boss_boss_4`。
- 旧 `recordTrigger(MOON_AVATAR_ENTRY_ID)`：记 `codex_boss_boss_4`。

**结论**：二者**同 entryId**，`recordTrigger` 在 `recordKill` 之后为 **same-id 幂等 no-op**（`CodexTracker.record` 首次置位、二次返回 false）——**不冲突、不双解锁、不重复记账**。
**权威路径 = `recordKill('boss_4')`**（与条目 `unlock:'kill'` 元数据一致，且是隐藏条目真正解锁点）。`recordTrigger(MOON_AVATAR_ENTRY_ID)` 保留为**显式 trigger 语义调用**（幂等、零副作用），满足"分支可达"要求，但**非第二权威源**。已在 `kill-loot-consumer.ts:139-146` 写明裁决。

### 4.4 功绩口径（重要裁决）
化身（`kind='boss'`）**不计入**「首杀 Boss/精英 +2/只」；化身走专属 `avatarKills*5`。即**一次化身击杀 = 功绩 +5**（对齐任务书「化身产出…功绩 +5」）。地图 Boss → `firstBossKills*2`。二者互斥（`if (contentId==='boss_4') … else if (kind==='boss'\|\|kind==='tank')`）。**此项列为需主理人确认项（§7 存疑项 C）**。

## 5. `bossId` 落地后 census #9 修复验证

- **审查 #9 原文**：Boss/化身遥测 `enemyId` 落空 → 按 `enemyId` 归组的 census 显示 `id=?`（`代码侧审查-2026-09-23.md` 主表 #9 / M6）。
- **核查**：全仓 `grep -i census` **仅命中两份人工文档**（`代码侧审查-2026-09-23.md`、`...ai-auto-test.md`），**不存在代码侧 census 采集点**——census 是 AI 自动测试的**人工产物**，其 `id=?` 源自击杀实体 `enemyId===null`。
- **本批修复**：Boss/化身实体现携带 `bossId`，且 `EnemyKilled` payload 透出 `bossId`（`enemy.ts:363`）。**任何从击杀载荷取 id 的采集点**（含未来脚本化 census）改读 `payload.bossId ?? payload.enemyId` 即得 `boss_1/2/3/4`。
- **验证**：`avatar-defeat.test.ts` 断言化身/地图 Boss/内容敌三类击杀 payload 分流后 `codex` 均收到正确内容 ID（`kill:boss_4` / `kill:boss_1` / `kill:enemy_g1_1`），即 payload 内容 ID 现**必然可解析**。
- **残留**：需在 AI 自动测试脚本侧或后续遥测批次把 census 取值改为 `bossId ?? enemyId`（本批范围外，登记于 §7 未做项）。

## 7. 未做 / 存疑 / 需主理人拍板项

### A. `bossId` 声明位置（工程判断，建议知悉）
任务书要求 `boss.ts` 加 `bossId: BossId | null = null`，同时要求 `Enemy` 基类有默认值。因 `kill()` 与 `spawnByBossConfig()` 均在 **`Enemy` 基类**、且非 Boss 实体（15 内容敌 / 召唤物 / 幻影）需默认值，**字段实现在基类 `Enemy`**（单一来源，避免子类字段 shadowing 与 `useDefineForClassFields` 下的重复初始化）。`Boss extends Enemy` 天然继承，`boss.ts` 类头已注释说明。**未在 `boss.ts` 重复声明**。

### B. 二次 `EnemyKilled` 订阅（受既有守卫约束）
`tests/unit/review-f-f.test.ts:208-210` 断言 `PlayScene` 必须**逐字**保留 `GameEvents.on(GameEvent.EnemyKilled, (args) => this.killLoot.onEnemyKilled(args), this)`，且 **禁止**出现 `private onEnemyKilled(`。故化身分流采用**第二条订阅**（保留首条逐字不变）+ 新私有方法 `onAvatarKilled`（订阅序在后 → 产出链先结算）。**未新增 GameEvent**（`core/events.ts` 不在本批允许清单内）。

### C. 化身功绩口径（**已闭环 · 设计侧确认**）
化身 `kind='boss'`，若沿用原 `kind==='boss'` 判据会同时计「首杀 Boss +2」与「化身 +5」= **+7**。本批按任务书口径**只计 +5**（`avatarKills`）。
