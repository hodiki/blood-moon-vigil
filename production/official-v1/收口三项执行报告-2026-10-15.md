- **缓存**：`actions/setup-node@v4` + `cache: npm`（`node_modules` 由 `npm ci` 重建）。
- **步骤链**（严格按主理人指定顺序）：
  1. `actions/checkout@v4`

## C · N1 沙盘重校 —— 判定结论：**沙盘不消费该分母 → 不跑批（降级为遥测侧待实测项）**

**判定（关键，先说结论）**：`tools/sim/**` **不读取** `runStats.totalDamageDealt` / `recordTotalDamage` / `relicDpsShareOf()` / `derivativeDpsShareOf()` —— 沙盘输出与本变更（分母纳入 Boss 面板 HP）**无交集，N1 无需重校**。

**证据（文件:行）：**
1. **符号零命中**：在 `tools/sim/` 内 `grep` 检索 `totalDamageDealt | recordTotalDamage | relicDpsShare | derivativeDamageShare | relicDpsShareOf | derivativeDpsShareOf` → **No matches found**（0 命中）。
2. **模块零依赖**：`tools/sim/` 全目录**不 import** `@/stats/run-stats`（`RunStats` / `RunResult`）。`batch-calib.ts:13` 只 import `./sim-run`；`sim-run.ts:16~45` 的 import 清单**无** run-stats。沙盘有**自己独立**的伤害累加器 `sim-run.ts:189 damageDealtWindow`（仅用于 `dpsCurve` 分桶，见 `:522/:587/:607`），与生产 `RunStats` 分母**完全无关**。
3. **文档佐证**：`tools/sim/README-sim.md` **§5 已知不可信项**明记「**圣物占比（演出型恒 0）**」——沙盘根本不建模圣物占比，自然不会消费其分母。
4. **变更归属运行时**：分母纳入 Boss HP 的实际写入点在**生产运行时** `src/scenes/run/kill-loot-consumer.ts:133`（`if (cfg?.hp) p.runStats().recordTotalDamage(cfg.hp)`，`contentId = bossId ?? enemyId`），消费端为 `RunResult.relicDpsShare / derivativeDpsShare`（`run-stats.ts:364-365`）→ **遥测 / e2e 侧**，非沙盘。
5. **测试不破**：`tests/unit/exclusive/relic-redline.test.ts:18` 用**硬编码**分析分母 `REF_TOTAL_DAMAGE = 17600`（GDD 尾章 440×40），纯算式断言，**不依赖运行时分母** → 批 D 变更**不破测**（印证 `当前版本收口待办-2026-10-09.md` N1 行「不破测」）。

**处置（降级登记）：** N1 由「沙盘重校」**降级为「遥测侧待实测项」**——
- **判据对象**：实机单局 `RunResult.relicDpsShare`（圣物 `<5%` 红线）与 `derivativeDpsShare`（衍生技 `12~18%` 目标）。
- **影响方向**：分母纳入 Boss 面板 HP（3000~4500）→ 分母 ↑ → 两占比 ↓（主理人/批 D 已认定为**有意修正**，Boss HP 本属「全源总伤」，见 `src/enemies/enemy.ts:42-46`）。

- **为什么本机不跑批**：① 沙盘不消费该分母（跑批**无信息增量**）；② 规避 `vite-node` 与门禁期 `vite build`/`vitest` 的 `.vite` 变换缓存争用（主理人明令 C 在门禁后、防争用；既然判定不消费，直接省去）。
