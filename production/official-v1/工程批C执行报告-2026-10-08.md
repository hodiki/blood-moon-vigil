## 二、接线实现说明

### 2.1 `new OathkeeperRuntime` 传入什么

```ts
// src/scenes/PlayScene.ts:486
this.oathkeeper = new OathkeeperRuntime(this.player.x + 40, this.player.y, this.player.stats.maxHp);
//                                                                     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 新增第 3 参 = 玩家「当局当前」最大生命
```

构造签名（`oathkeeper-runtime.ts:50`）：`constructor(x = 0, y = 0, playerMaxHp?: number)`，内部
`createOathkeeperState(x, y, playerMaxHp)` → `maxHp = oathkeeperMaxHp(playerMaxHp) = playerMaxHp × 1.5`。

**关键时序**：构造点（486）早于一切 HUD emit，且 `treeApplier.applyToStats`（`PlayScene.ts:297`）**早于**守誓者装配 → 传入的 `stats.maxHp` **已含**角色初始 HP + 天赋树生存节点加成。故「入场初始化」即反映玩家真实面板，**不取兜底 172.5**。

### 2.2 `syncMaxHp`（等价机制）在哪些触发点被调用

**单一接线点**：`PlayScene.ts:659-668` 订阅全局事件 `GameEvent.HpChanged`（payload `{ hp, maxHp }`）：

```ts
GameEvents.on(GameEvent.HpChanged, (args: unknown) => {
  this.oathkeeper.syncMaxHp((args as { maxHp: number }).maxHp);
}, this);
```

`HpChanged` 是玩家 HP/上限变化的**统一出口**（`core/events.ts:101-102` 已登记 payload 含 `maxHp`）。**所有运行期 maxHp 变更源在写回后都会 emit 此事件**，故单点订阅即覆盖全部来源；`maxHp` 未变（纯受击 / 治疗）时 `syncMaxHp` 幂等（详见 §四）。守誓者未启用（非修女 / 非圣铃）时该调用为无害空写。

### 2.3 maxHp 来源清单（逐一核对）

## 四、上限提升后当前 HP 的处理选择与理由

**实现位置**：`oathkeeper.ts:87-92` `syncOathkeeperMaxHp()`（工程批 A 已落，本批补充口径理由注释，逻辑未改）：

```ts
const next = oathkeeperMaxHp(playerMaxHp);
const wasFull = state.hp >= state.maxHp;
state.maxHp = next;
state.hp = wasFull ? next : Math.min(state.hp, next);
```

**选定口径**：
- **同步前「满血」→ 同步后仍满血**：当前 HP 随新上限一并抬升到顶；
- **同步前「未满血」→ 只抬上限、当前 HP 保持绝对值不变**（仅当当前值 > 新上限时钳制，不溢出）。

**理由（显式选择，不留含糊）**：
1. **无伤态自然成长**：守誓者是玩家「生命的延伸」替身。满血 = 未受伤，新上限即新的满血值，当前值跟着到顶**不构成「治疗」**（它本就没掉血）。
2. **负伤态保留创伤**：当前 HP 为绝对量，不因玩家升级 / 加生命上限而被「顺手治愈」——避免「玩家成长白嫖守誓者回血」的廉价收益，也不产生任何溢出。
3. **与入场语义自洽**：`createOathkeeperState`（入场即满血 = 上限）与此口径一致——上限只随玩家成长移动，受伤 / 治愈仍由 `transferDamage` / `healCompanion` / `tickTombstone` 独立驱动。

**断言覆盖**：`oathkeeper-maxhp-sync.test.ts`「满血保持满血」「负伤保留创伤 + 超上限钳制」两条用例将上述三态全部钉死。
