### D1 · 天赋树三桶红线口径 + 降档

**事实底数（工程真值，`talent-tree.ts` / `tree-state.ts`）**：

| 桶 | 现实现（漏 `_2`） | **补 `_2` 后实算** | 红线 | 判定 |
|---|---|---|---|---|
| 伤害 | 5.0% | **6.6%** | ≤8% | ✓ |
| 生存 | 3.4% | **4.1%** | ≤6% | ✓ |
| 合成（= d+s） | 8.4% | **10.7%** | ≤10% | ✗ **破线** |

- 漏算原因：`tree-state.ts:231 bucketEquiv()` 用 `TALENT_BUCKET_EQUIV[bucket][node.id]` 查表，而表键只有基础 id（`a_attack` / `a_damage` / `a_life`…），**子节点 `a_attack_2` / `a_damage_2` / `a_life_2` 查不到 → 各自被静默跳过**（`if (per)` 为假）。→ 现实现给出 8.4% 的**假 PASS**（与审查 A-13 一致）。
- 另：12 个支线节点（`br_*`）**无 `bucket` 字段**，完全不进红线折算；但 §4.3 要求「支线效果计入所属三桶折算」→ 亦属 D1 缺口。

**「合成」口径 3 案（定义式 + 推荐）**：

- **口径 α（串联和 = d + s，推荐）**：合成 = 伤害桶等效 + 生存桶等效（**tempo 桶不计**）。红线 `d ≤ 8% ∧ s ≤ 6% ∧ d+s ≤ 10%`。
  - 优点：与工程现实现（`allTreeBonusesWithinRedline` 的 `d+s <= combined`）**完全一致**——改动最小；最严、最直观、可断言。缺点：8%+6%=14% 的名义上限与 10% 合成上限不能同时取满，须在 §6.1 显式说明「合成是更紧的耦合约束」。**采 α 则 §6.1 的「≈7~8% / ≈5~6%」必须下压至和 ≤10%（如 6.5% / 3.5%）**。
- **口径 β（加权和 = d + w·s）**：合成 = d + 0.7·s（生存等效打折，因生存不直接换算输出）。红线 ≤10%。优点：允许「输出流」买伤害、少买生存；缺点：需为 w 给论证、断言之式需改、跨文档解释成本高。
- **口径 γ（独立第三指标）**：合成 = 开局质变叠加强度增量（b/d/s1 共存带来的开局面板 ×），与 d/s 正交。红线 ≤10%。优点：贴合 B-9「开局强度」风险；缺点：**需新埋点/新指标**，工程量大，本次不具可落地性。

**§6.1 内部不自洽的消除**（B-1：7~8 + 5~6 = 12~14% > 10%）——采 α 时二选一：
- **修法 i（推荐）**：§6.1 三行改为「伤害 ≈6.5% / 生存 ≈3.5% / 合成 ≤10%（= d+s）」，与补 `_2` 后实算 6.6%/4.1% **对齐并留余量**（实算 → 需配合降档，见下）。
- **修法 ii**：保留 7~8 / 5~6，把「合成」明确为口径 γ 的独立指标（**不推荐**：工程不可落地）。

**降档预案 2 案**（补 `_2` 后 d+s = 10.7%，超 10% → 触发降档；下方两案对 `s` 等量 −0.7pp）：

| 案 | 改法 | 折算键同步 | `s` 变化 | `d+s` | 6min 成型强度影响 | 玩家可感 | 副作用 |
|---|---|---|---|---|---|---|---|
| **降档 1** 单点 +15→+10 | `TALENT_ATTRIBUTE_EFFECTS.a_life.maxHp: 15→10` | `a_life` 等效 0.7→**0.47**（按 HP 比例） | 4.1→**3.4** | **10.0**（压线） | 满树生命 −15 HP | 中（每层收益变小，但 3 层成长颗粒保留） | 压线无余量；浮点断言风险 |
| **降档 2** 层数 3→2 | `a_life` maxPurchases 2→1（或移除 `a_life_2`） | 系数不变 | 4.1→**3.4** | **10.0**（压线） | 满树生命 −15 HP（同 1） | 中（少一个可点亮位） | 压线无余量；成长颗粒少 1 |

> ⚠ 两案效果等量、均压线 10.0，**均无余量**。建议：配合「伤害桶微降」（如 `a_cooldown` 层数 2→1，或系数下修）留 ≥0.5pp 余量，或将验收目标设为 **9.5%**（红线仍 10%）。
> ⚠ **降档会改变玩家体感（生命成长变薄）——属体验变更，本次不落地**。请主理人在「口径 α + 降档 1 / 降档 2 / 组合（含伤害侧微降）」三者中拍板后，我再回写 GDD 并更新 §6.1。

**案 D 的三个落法（红线维持 ≤10%）**：

**🔑 关键判断（必须写出的推荐理由）**：

1. **A / B 一律让数值恰好压在 10.0、零余量**——这不是「解决」，而是「擦线过关」。今后**任何一处新增**（新增属性节点、支线效果计入三桶折算 EN-03 落地、`violet-fallen` 支线②改通用范围节点、图鉴联动节点扩充等）都会**立刻再次越线**；且红线断言 `d+s <= 0.10` 在浮点 10.0000001 时会误判，**零余量 = 长期维护债**。
2. **C（放宽 11%）只换来 0.3pp 余量**——与 A/B 的 0pp 同量级的脆弱，同样挡不住下一次新增；且代价是**直接削弱设计目的**：`合成 ≤10%` 是 GT-5 三桶预算的**耦合闸门**、是 §2 支柱 2「局外数值不与怪物域难度提升赛跑」与支柱 4「难度空间不被局外数值平移侵占」的量化落点。放宽 1pp 等于**允许局外数值再多侵占 1pp 的难度余量**，与红线的初衷背道而驰；名义上限 8%+6%=14% 仍 >11%，耦合关系并未简化——属「迁就实测」而非「设计意图」，是**支柱漂移**的先例。
3. **推荐采 D（建议 D-1 或 D-2，落 ≈9.5%）**：红线保持 ≤10% 的**设计意图不变**，同时**留 0.5pp 安全垫**容纳今后新增节点/支线折算落地；体感代价与 A/B 同级（生命成长变薄，属**体验变更**），但换来红线**可长期维持**。若主理人希望更强缓冲，取 **D-3（≈8.8%，余量 1.2pp）**。
