## 给 Hodiki / 其它 Agent 的一段话（先读这段）

GPU 机 **HodikiX**（`192.168.101.200`）上的维护文档不再靠 U 盘或聊天拷文件。  
`D:\ComfyUI\docs` 用 Windows **目录联接（方案 A）**挂到 Comfy 用户目录 `user\default\env-docs`。编码机 **Hodiki**（仅 `192.168.101.82`）继续走已放行的 **TCP 8188**，用 Comfy 自带的 `/userdata` 拉取，本机改文档后对端立刻能读到最新内容。

不要请求 `/docs`——那是 Comfy 前端节点说明书，会 403，不是这份维护文档。  
`/userdata/{file}` 只认**一段**路径，目录分隔符必须写成 `%2F`。

```text
健康：    GET http://192.168.101.200:8188/system_stats
列文档：  GET http://192.168.101.200:8188/userdata?dir=env-docs&full_info=true
读说明：  GET http://192.168.101.200:8188/userdata/env-docs%2F环境说明.md
读本记录：GET http://192.168.101.200:8188/userdata/env-docs%2F局域网通信维护记录.md
握手：    GET http://192.168.101.200:8188/userdata/comfy-lan-handshake.json
参考工作流：GET http://192.168.101.200:8188/userdata?dir=workflows
```

握手 JSON 里的 `docs` 字段与上表一致。本机不冻 walk / skill API。

## 2. 方案 A 是什么（记录）

**目的**：本机 `docs\` 一改，局域网 Hodiki / 其对端 Agent 马上能取到，不再等人传文件。

**做法（2026-09-08 落地）**：

1. 目录联接：`D:\ComfyUI\user\default\env-docs` → `D:\ComfyUI\docs`
2. 硬链接：`D:\ComfyUI\user\default\comfy-lan-handshake.json` ↔ `D:\ComfyUI\comfy-lan-handshake.json`
3. 不新开端口、不改防火墙、不改 `server.py`、不另起进程
4. 沿用已验证的 `/userdata`（参考工作流本来就能列、能下）

**为什么不用别的**：

- Comfy 的 `/docs` 已被前端占用，且 403
- 当前 WLAN 是 Public，SMB 共享别扭，也对端 Agent 不友好
- 独立小 HTTP / Syncthing / Git 对这几个文本文件过重

**维护注意**：

- 只改 `D:\ComfyUI\docs\` 或 `D:\ComfyUI\comfy-lan-handshake.json`，不要在联接上再套一层拷贝，也不要靠 Documents / 桌面同步。
- 不要删 `user\default\env-docs` 联接；坏了用：  
  `mklink /J "D:\ComfyUI\user\default\env-docs" "D:\ComfyUI\docs"`
- 握手硬链接坏了用：  
  `mklink /H "D:\ComfyUI\user\default\comfy-lan-handshake.json" "D:\ComfyUI\comfy-lan-handshake.json"`
- 升级 Comfy 核心一般不必重做；若 `user\default` 被重置，按上面两条重建。
