# ADR-004：升级选卡 / 结算 / HUD 采用原生 HTML 覆盖层（而非 Phaser DOM 元素）

> 状态：**已接受** · 日期：Phase 3 · 作者：程基岩（工程主程）
> 关联：`architecture.md` §4.4、`adr-003.md`（暂停联动）· 上游：`upgrade-pool.md` §④（卡片规格）、`art-bible.md` §6（UI 规范）/§9（可访问性）

## 背景

升级三选一是支柱 2 的核心交互（每 30–90s 一次，全屏暂停选卡），结算页与 HUD 也是高频 UI。渲染 UI 的候选路径有三：
1. **Phaser 内建 UI 对象**（`GameObjects.Text` / `Image` / `Container`）；
2. **Phaser DOM 元素**（`this.add.dom(x, y, element)`，需 `dom.createContainer: true`）；
3. **原生 HTML 覆盖层**（独立于 canvas 的 `div`，绝对定位覆盖游戏容器）。

约束来自设计文档：
- upgrade-pool §④：三张 320×180 卡片、图标 128×128、标题 + 描述 + 数值、选中态 2px 冷青描边 + 缩放 1.03、80% 黑遮罩、卡片上浮动画、30s 超时自动选择。
- art-bible §6：热区移动 ≥44×44、桌面 ≥32×32；字号下限 16px / 标题 ≥22px / 移动端物理 ≥14px。
- art-bible §9 可访问性：系统级字体缩放、弹窗文字 125% 档、高对比模式、减少闪烁开关。
- ADR-003：LEVEL_UP/PAUSED 时 `tweens.pauseAll()`——Phaser tween 驱动的 UI 动画会被暂停。

## 决策

**升级选卡、结算页、HUD 全部采用「原生 HTML 覆盖层」（DOM overlay）：一个绝对定位的 `#ui-overlay` 层盖在 Phaser canvas 之上，CSS 负责布局与动画，DOM 事件负责交互。**

```
┌─────────────────────────────────────┐
│  Phaser.Game (canvas, 游戏世界)      │ ← 游戏渲染，不画 UI
├─────────────────────────────────────┤
│  #ui-overlay (position:absolute)     │ ← HUD / 升级卡 / 结算，HTML+CSS
└─────────────────────────────────────┘
```

1. **结构**：`index.html` 里 `#game-root`（相对定位）包含 `<canvas>`（Phaser parent）与 `#ui-overlay`；`ui/` 下各模块（hud/levelup-overlay/results）以**类**封装 DOM 构建与事件，不直接裸操作 DOM。
2. **交互**：升级选卡/结算时 `#ui-overlay` 可交互（`pointer-events: auto`），canvas 被 80% 黑遮罩盖住且不可点（防误触；upgrade-pool §6.4 双端禁用拖拽误触）；RUNNING 态 overlay 仅 HUD 数值区域可点，其余 `pointer-events: none` 放行给游戏。
3. **动画**：卡片上浮/缩放 1.03/遮罩淡入用 **CSS transition/animation**——不受 `tweens.pauseAll()` 影响（ADR-003 联动），暂停态 UI 照常动、游戏世界静止。
4. **对齐**：升级卡/结算为全屏居中，天然覆盖整个视口，与游戏内坐标无关；HUD 用 CSS 百分比/固定尺寸贴边（art-bible §6 左上/左下/右上），与 Phaser 分辨率解耦。
5. **可访问性**：系统字体缩放、125% 弹窗文字、高对比、减少闪烁开关全部由 CSS/JS 原生能力承担（art-bible §9），无需 Phaser 适配。
6. **数据流**：overlay **只读**游戏状态、**只发事件**（`GameEvents.emit('upgrade:chosen', ...)`），不直接改玩法状态（单向数据流，见 architecture.md §2 铁律）。

## 后果

**正面**：
- 触控热区 ≥44px、字号下限、无障碍天然满足；Phaser 文本/容器方案做这些需大量手写适配。
- **不占 WebGL draw call**（特效 draw call ≤8 预算更宽裕；Phaser Text 每对象独立 draw call，HUD+选卡会造成 draw call 上升）。
- 暂停语义干净：UI 动画与游戏世界互不干扰（ADR-003）。
- 前端开发者零学习成本——就是 React/Vue 熟悉的 DOM/CSS。

**负面**：
- canvas 与 DOM overlay 是两套渲染管线，视觉需人工对齐（配色抄 art-bible 色板，不自动同步）。
- 缩放跟随：Scale.FIT 下 canvas 尺寸变化，overlay 需监听 `resize` 用 CSS 单位自适应（升级卡/结算用视口单位即可，HUD 用百分比）。
- 双端触摸事件需防：overlay 覆盖区域要精确控制 `pointer-events`，避免挡游戏输入（RUNNING 时只有 HUD 小区域可点）。

**缓解**：
- 统一 `ui/overlay-host.ts` 封装 overlay 根节点与 resize 适配，各 UI 模块只写内容。
- `pointer-events` 规则写入 `control-manifest.md`，实现与测试都按表核对。
- 若未来需要"UI 跟随游戏内物体"（如 Boss 血条顶部 UI 也可用 CSS 百分比完成），不引入 `add.dom`。

## 备选方案

| 方案 | 评价 |
|---|---|
| **Phaser 内建对象（Text/Container/Image）** | 在游戏坐标系内最"原生"，但 Text 每对象 draw call 高（破坏 ≤8 预算）、热区/字号缩放/无障碍需手写、动画被 `tweens.pauseAll()` 暂停（与 ADR-003 冲突）。**否决** |
| **Phaser DOM 元素（`this.add.dom`）** | 能用 HTML/CSS，但元素挂进 Phaser 场景树，随相机/缩放变换，Scale.FIT 下坐标换算复杂；且仍受 Phaser 生命周期影响。**否决** |
| **原生 HTML 覆盖层（选中）** | 见上"正面"。唯一代价是两套渲染管线的视觉对齐纪律，可接受。**接受** |

## 验收核对

- upgrade-pool §④ 卡片规格（320×180、图标 128×128、选中描边 + 缩放 1.03、80% 黑遮罩、上浮动画）由 CSS 实现 ✔。
- upgrade-pool §6.1 超时 30s 自动选第 1 张：overlay 挂 `setTimeout`，且 GameState 在 LEVEL_UP 态仍走 update 超时检查 ✔。
- art-bible §6 热区/字号、§9 无障碍（字体缩放/125% 档/高对比/减少闪烁）由 DOM/CSS 原生承担 ✔。
- 特效 draw call ≤8：HUD/UI 零 WebGL draw call ✔（architecture-review §4 核算）。
