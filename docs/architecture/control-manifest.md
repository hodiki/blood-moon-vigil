## 0. 读法说明

- **「热区」** = 可点/可触的有效响应区域尺寸（含视觉外扩），非视觉尺寸。
- **「行为」** = 触发后的游戏内效果，与 `GamePhase` 状态机联动（见 §5）。
- 测试验收时逐条勾选 §6 验收清单；任何改动以本清单为准，偏离即修改本文件并评审。

## 1. 移动输入（核心输入，支柱 1 唯一操作）

### 1.1 桌面（KeyboardInput）

| # | 键位 | 行为 | 备注 |
|---|---|---|---|
| M1 | `W` / `↑` | 向上移动 | 8 向合并 |
| M2 | `S` / `↓` | 向下移动 | 8 向合并 |
| M3 | `A` / `←` | 向左移动 | 8 向合并 |
| M4 | `D` / `→` | 向右移动 | 8 向合并 |
| M5 | 斜向组合（W+D 等） | 斜向移动 | **向量归一化**，斜向速度 = 单方向速度（防超速） |
| M6 | 全部松开 | 移动向量归零，角色静止 | |

输出：`getMove(): {x, y}`，长度 ≤1（`KeyboardInput` 只输出 0/1 归一化向量，无幅度）。

### 1.2 移动端（TouchInput：左半屏虚拟摇杆 · 常驻底座 + 任意处起手混合方案）

> **方案定案（主理人裁决 / ux-spec §2/§5）**：常驻底座 + 左半屏任意处起手。
> 空闲时底座固定在默认位（720×1280 设计空间 (180,1120)，ux-spec §2）；左半屏任意处
> `pointerdown` 起手时底座瞬移至按下点、原点=按下点（浮动语义），拖动输出向量；
> `pointerup` 归零、底座回常驻位（常驻语义）。既保证"拇指够得到、可盲操作"，
> 又保留"任意处起手"的舒适区（MOBA 半固定摇杆模式）。

| # | 手势 | 行为 | 热区 | 备注 |
|---|---|---|---|---|
| M7 | 左半屏任意处 `pointerdown` | 摇杆激活：底座瞬移至按下点，原点=按下点（任意处起手） | 触摸点即热区；底座常驻位 (180,1120) | 仅 **x < 屏宽/2** 响应；右半屏留给 UI/暂停键 |
| M8 | 拖动 | 摇杆拇指跟随，输出向量 = (位移 / 摇杆半径)，clamp 到 ≤1 | 底座半径 48px（视觉 96px 直径） | **死区**：中心 10% 内输出 (0,0)，防误触抖动 |
| M9 | `pointerup` / `pointercancel` | 向量归零，拇指隐藏，**底座回常驻位 (180,1120)** | | 摇杆贴图在 Phaser 内（effects 图集，E1 程序生成） |
| M10 | 升级选卡/暂停期间 | **摇杆隐藏**，不响应移动 | | upgrade-pool §7；由 `GameState` 切 LEVEL_UP/PAUSED 触发 |

输出：`getMove(): {x, y}`，长度 = 摇杆幅度（**幅度即速度百分比**，ADR-002）。

### 1.3 双端差异（移动输入）

| 项 | 桌面 | 移动 |
|---|---|---|
| 输入方式 | 离散按键 | 连续向量 |
| 向量幅度 | 恒 1（归一化） | 0–1（摇杆幅度） |
| 实现模块 | `keyboard-input.ts` | `touch-input.ts` |
| 归一化 | 斜向合并后归一化 | 位移 clamp 到半径 |
| 影响 | 玩家模块只依赖 `InputSource`，无感知 | 同左 |

### 3.1 交互规格

| # | 端 | 操作 | 行为 | 热区 |
|---|---|---|---|---|
| U1 | 桌面 | 鼠标点击卡片 | 选择该升级项，应用效果，回 RUNNING | **≥32×32px**（视觉 320×180 卡整卡可点，热区自动满足） |
| U2 | 移动 | 手指点按卡片 | 同 U1 | **≥44×44px** |
| U3 | 双端 | 不操作满 30s | 超时自动选**第 1 张**（防挂机卡死，upgrade-pool §6.1） | — |

| U5 | 双端 | 拖拽/长按 | 不响应（upgrade-pool §7 双端禁用拖拽误触，点按即选） | — |

### 3.2 卡片规格（对齐 upgrade-pool §④ / art-bible §6）

| 项 | 规格 |
|---|---|
| 布局 | 全屏居中 3 张，间距 24px |
| 卡片尺寸 | 320×180px（视觉） |
| 图标区 | 128×128px（上图标下文字） |
| 选中态 | 2px 冷青 `#54E6C9` 描边 + 缩放 1.03 |
| 背景 | 80% 黑遮罩（聚焦） |
| 字号 | 标题 ≥22px 加粗；正文 ≥16px；移动端物理 ≥14px（art-bible §6） |
| 动画 | 卡片上浮（CSS，不受暂停影响，ADR-004） |
| 触控 | 热区 ≥44×44（移动）/ ≥32×32（桌面） |

### 3.3 状态联动

```
经验达标 → GameEvents.emit('level:up') → GameState → LEVEL_UP（世界冻结）
→ upgrade-pool 抽 3 项 → levelup-overlay 渲染
→ 玩家选择 / 30s 超时 → GameEvents.emit('upgrade:chosen')
→ upgrade-apply 写回 → GameState → RUNNING（世界恢复）
```

### 9.1 E4 埋点说明（E4-S1/S2/S3 事件流与统计口径）

**HUD 事件流（DOM 0 draw call，ADR-004 单向数据流）**：

| 事件 | payload | 触发场景 |
|---|---|---|
| `xp:gem-collected` | `{ amount }` | 宝石拾取 → HUD 经验条累计 |
| `level:up` | `{ level, xpNeeded }` | 经验达标 → HUD 等级文本 + 经验条归零 |
| `hp:changed` | `{ hp, maxHp }` | 受击 / 升级回血 / 吸血 / 生命上限提升 → HUD 血条 |
| `weapon:unlocked` | `{ weaponId, name }` | 升级 1/2 号项解锁环/波 → 武器槽点亮 |
| `boss:spawned` / `boss:hp` / `boss:defeated` | `{ bossHp }` / `{ hp, maxHp }` / `{ bossHp }` | 20:00 Boss 出场 / 战内每帧 / 击杀 → 顶部 UI 血条显隐与填充 |

**统计埋点（`src/stats/run-stats.ts` 纯函数，供文策渊评审 / C9-留存数据源）**：

1. **纠结时刻**（upgrade-pool §⑧.3 / FUNC-E3-06）：停留 >3s 或「选项强度接近」→ `hesitationCount += 1`；判据单局 ≥3。
   「选项强度接近」操作化定义：三张全为机制改变型（工程代理指标，真机校准后回写）。
2. **升级时间戳**（design-review-e3 交接项 2）：`upgradeTimestamps`（局时秒），聚合 `firstLevelUpSeconds` /
   `lastUpgradeIntervalSeconds` / `reachedLevel47` —— 验证 Lv47 预警与后期升级间隔是否 <45s。
3. **Boss 战时长 / DPS**（交接项 4）：`bossFightSeconds`（击杀−出场局时秒）与 `bossDpsEstimate`（6000/时长）；
   **60~90s 为最终判据**（enemies §⑤）；>90s → 降 5000 或保底武器抽取（主理人拍板）。
4. **结算统计**（S10 / C9-留存）：`game:over { stats }` 含存活时间 / 击杀 / 等级 / build 回顾 / 纠结次数 ——
   C9-留存判据（中位存活 ≥10 分钟、再来一局 ≥50%）数据源。
